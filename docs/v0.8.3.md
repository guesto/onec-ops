# v0.8.3 — Проверка аргументов и путей платформы

## Исправлено

- В `dump-config`, `load-config`, `dump-cf` и `load-cf` пустое имя расширения
  или имя только из пробелов возвращает код 1 до запуска платформы. Подстановка
  пустой переменной `--extension "$EXT"` больше не выбирает основную конфигурацию
  молча. Проверка имени общая с командами работы с расширениями.
- Путь к платформе из CLI, `ONEC_OPS_PLATFORM` или TOML приводится к абсолютному
  относительно текущего рабочего каталога. `--platform ./1cv8` запускает файл
  из этого каталога, сохраняя приоритет CLI → окружение → конфиг → стандартный путь.
- Каталог не проходит проверку исполняемого файла платформы, включая dry-run.
- Открытие журнала и подготовка каталога ИБ преобразуют ошибки файловой системы
  в `OneCOpsError`. CLI возвращает код 1 с путём и причиной без traceback.
  Это включает файл вместо каталога ИБ, ошибку создания каталога и отказ удаления
  при принудительном пересоздании.

## Проверка

- 19 новых регрессионных проверок воспроизводили ошибки до исправления.
- Полный набор: 506 тестов, покрытие 98%; Ruff и `git diff --check` без ошибок.
- 9 сценариев через реальный CLI с имитацией платформы: относительный путь
  из каждого источника, каталог вместо файла платформы, пустое и пробельное имя
  расширения, ошибочные пути журнала и ИБ, успешная запись журнала.
- Проверки выполнены на Linux с Python 3.14.4. Реальные базы 1С и GUI в этом
  прогоне не использовались; поведение GUI-таймаута не менялось.

Версия Python-пакета — `0.8.3`. Публикация в PyPI не входит в этот патч.

# ТЗ v0.7.0 — Обновление конфигурации БД (update-db)

## Цель

Отдельная команда `update-db` применяет к базе данных конфигурацию, 
которая уже загружена в ИБ (`/UpdateDBCfg`), без повторной загрузки.

## Зачем

Сейчас применить конфигурацию к БД можно только вместе с загрузкой 
(`load-cf --update-db-cfg`, `load-config --update-db-cfg`). Не покрыто:

- `repo-update` получает конфигурацию из хранилища, но **не применяет** 
  её к БД — нужен отдельный шаг;
- загрузка без `--update-db-cfg` (например, чтобы сначала проверить 
  расширения), после которой конфигурацию нужно применить;
- применение только одного расширения или всех расширений;
- динамическое обновление (без монопольного доступа к базе).

## Поведение 1С (проверено на 8.5.1.1343)

| Ситуация | Результат `/UpdateDBCfg` |
| --- | --- |
| Изменений нет | код 0, пустой `/Out` |
| Есть новые объекты | код 0, «Новый объект: …», «Обновление конфигурации успешно завершено» |
| Объекты удалены из конфигурации | код 0, «Объект удален: …» — **таблицы и данные удаляются без подтверждения**, даже с `-WarningsAsErrors` |
| `-Dynamic+` / `-Dynamic-` | работают на файловой ИБ |
| `-Extension <имя>` / `-AllExtensions` | применяют расширение / все расширения |

`load-cf --extension … --update-db-cfg` применяет и расширение: 
`-Extension` относится ко всей команде — исправлять не нужно.

## Архитектура

    scripts/actions/update_db.py         # update-db
    scripts/actions/extension_target.py  # необязательный выбор расширения

## Функциональные требования

### F-1. update-db

    onec-ops update-db --ib <путь> [--extension <имя> | --all-extensions]
      [--dynamic | --no-dynamic] [--warnings-as-errors]

    DESIGNER /F <ib> /DisableStartupDialogs /UpdateDBCfg
      [-Extension <имя> | -AllExtensions] [-Dynamic+ | -Dynamic-] [-WarningsAsErrors]

- Без выбора расширения — основная конфигурация.
- `--extension` и `--all-extensions` взаимоисключающие; пустое имя — ошибка. 
  В отличие от `check-extension` / `delete-extension` выбор **не обязателен**.
- `--dynamic` → `-Dynamic+`, `--no-dynamic` → `-Dynamic-`; без флага 
  ключ не передаётся (решает платформа).
- `--warnings-as-errors` → `-WarningsAsErrors`.
- Поддерживает `--ib-user` / `--ib-password` и `--dry-run`.

### F-2. Предупреждение и результат

- Перед запуском — WARNING: объекты, удалённые из конфигурации, будут 
  удалены из БД вместе с данными.
- Интерактивного подтверждения нет — как у `load-cf --update-db-cfg`; 
  команда не меняет конфигурацию, а применяет уже загруженную. 
  Защита от ошибок агента — правило безопасности в Skill.
- После успешного запуска: пустой `/Out` → INFO «Изменений нет: 
  конфигурация БД актуальна»; иначе — INFO «Конфигурация БД обновлена» 
  (подробности 1С уже в журнале — v0.5.2).

## Критерии приёмки

На копии тестовой базы:

- AC-1. `load-cf` без `--update-db-cfg` → `update-db` — код 0, 
  «Конфигурация БД обновлена»; повторный `update-db` — «Изменений нет».
- AC-2. `repo-update` → `update-db` применяет конфигурацию из хранилища.
- AC-3. `update-db --extension onec` применяет загруженное расширение.
- AC-4. `update-db --dynamic` — код 0.
- AC-5. `pytest` зелёный, покрытие не ниже 97%; `ruff check` чистый.
- AC-6. Skill: `update-db` в таблице и в списке разрушающих команд; 
  сценарий «хранилище → БД» в `references/workflows.md`; 
  `references/commands.md`, README, CHANGELOG, roadmap.

## Что вне scope v0.7.0

- Фоновое обновление (`-BackgroundStart`, `-BackgroundFinish` и др.) 
  и `-SessionTerminate` — для клиент-серверных баз (v0.3.1).
- `--update-db-cfg` у `repo-update` — достаточно `update-db` следующим шагом.
- Предварительный просмотр изменений структуры БД.

## Результаты проверки на реальной 1С (8.5.1.1343)

- AC-1: новая ИБ → `load-cf` без `--update-db-cfg` → `update-db`: 
  «Новый объект: Справочник.Номенклатура…», код 0; повторный `update-db` — 
  «Изменений нет: конфигурация БД актуальна».
- AC-2: `repo-add-user dev` → `repo-bind` новой ИБ под `dev` → `update-db`: 
  объекты из хранилища появились в БД. `repo-bind` и `repo-update` меняют 
  только конфигурацию ИБ — без `update-db` БД остаётся прежней.
- AC-3 / AC-4: `load-cf` расширения → `update-db --extension onec --dynamic`: 
  «Новый объект: Справочник.onecСправочник1», «Конфигурация БД обновлена»; 
  `--all-extensions --no-dynamic --warnings-as-errors` — «Изменений нет».
- AC-5: 461 тест, покрытие 97%, `ruff check` чистый.

## Найдено при проверке

- Сценарий «Вторая база в хранилище» в `references/workflows.md` (v0.8.0) 
  не применял конфигурацию к БД — добавлен шаг `update-db`.
- `repo-update` на ИБ, которая никогда не подключалась к хранилищу, 
  завершается с кодом 0 и загружает конфигурацию (в v0.5.0 проверялся 
  только случай отвязанной после перепривязки базы — там код 1). 
  Поведение не меняли.

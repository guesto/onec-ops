# v0.9.4 — Патч: create-ib и путь конфига на Windows

## Цель

Отзыв пользователя с Windows (opencode + DeepSeek): `load-config`, `load-epf`,
`dump-epf` работают, но:

1. `create-ib` падает с «Неверные или отсутствующие параметры соединения» — ИБ
   пришлось создавать вручную.
2. В документации путь конфига `~/.config/onec-ops/config.toml`, а на Windows
   реальный путь `%LOCALAPPDATA%\onec-ops\onec-ops\config.toml`: конфиг с
   платформой не подхватился с первого раза.

## create-ib на Windows

Причина — открытый вопрос из v0.8.4. Строка соединения передаётся одним
аргументом `File="<путь>"`. На Windows `subprocess` собирает командную строку
по правилам MSVCRT и превращает кавычку внутри аргумента в `\"`; 1С разбирает
командную строку сама и получает `File=\"C:\ib\"`. В Linux аргументы
передаются массивом, поэтому там ошибки не было.

- `runner.RawArg` — аргумент, который на Windows попадает в командную строку как
  есть. Остальные аргументы по-прежнему экранирует `subprocess.list2cmdline`.
- Если в команде есть `RawArg`, на Windows `Popen` получает готовую строку
  (`windows_command_line`), иначе — список, как раньше. Linux не меняется.
- `create-ib` передаёт `File="<путь>"` как `RawArg`. Итоговая строка совпадает с
  ручным запуском `1cv8.exe CREATEINFOBASE File="C:\Базы\ib" ...`.
- Двойная кавычка в пути по-прежнему отклоняется до запуска 1С.

## Путь конфига

Путь конфига не меняется: перенос сломал бы уже настроенные машины.

- `config.default_config_path()` — путь по умолчанию для текущей ОС.
- `--help` показывает фактический путь у `--config`.
- `--dry-run` пишет строку «Конфиг (по умолчанию|--config): <путь> — найден /
  не найден».
- Ошибка «Платформа 1С не найдена» дополняется той же строкой.
- `references/commands.md`, `references/troubleshooting.md`, README: пути для
  Linux и Windows вместо одного `~/.config/...`.

- Юнит-тесты: сборка командной строки Windows с `RawArg` и без, передача строки
  в `Popen` только на Windows, `RawArg` сохраняется после добавления `/Out`,

## Проверка на Windows

Для пользователя с Windows и установленной 1С. PowerShell, каталог `C:\Temp`
можно заменить любым.

1. Обновить пакет и навык, проверить версию (`onec-ops 0.9.4`):

       pipx upgrade onec-ops
       onec-ops install-skill
       onec-ops --version

2. Путь конфига: `onec-ops --help` — у `--config` должен быть путь
   `C:\Users\<имя>\AppData\Local\onec-ops\onec-ops\config.toml`.
3. Dry-run показывает команду и конфиг:

       onec-ops --dry-run create-ib --type file --path "C:\Temp\onec ib тест"

   В журнале: `File="C:\Temp\onec ib тест"` и строка «Конфиг (по умолчанию): …
   — найден» (или «не найден», если конфига нет).
4. Создание ИБ без пробела и с пробелом и кириллицей — оба с кодом 0, в
   каталоге появляется `1Cv8.1CD`:

       onec-ops create-ib --type file --path C:\Temp\onecib1
       onec-ops create-ib --type file --path "C:\Temp\onec ib тест"

5. Созданная база открывается: `onec-ops --ib "C:\Temp\onec ib тест" dump-config --to C:\Temp\onecxml`
   — код 0.
6. Ошибка платформы показывает конфиг:

       onec-ops --platform C:\nope\1cv8.exe --dry-run create-ib --type file --path C:\Temp\x

   Последняя строка — «Конфиг (по умолчанию): …\onec-ops\onec-ops\config.toml — …».

Прислать: вывод шагов 2–6 (или только упавших), версию Windows и 1С.

## Результат проверки на Windows

Windows 10 (19045), 1С 8.5.1.1522, opencode + DeepSeek: все шаги успешны.
`File="C:\Temp\onec ib тест"` без экранирования, обе ИБ созданы, `dump-config`
из базы с пробелом в пути — код 0, ошибка платформы заканчивается строкой
«Конфиг (по умолчанию): …\onec-ops\onec-ops\config.toml — найден».
До проверки пришлось переустановить пакет: старая установка из GitHub
(`No module named 'scripts'`) не переходит на PyPI через `pipx upgrade`.

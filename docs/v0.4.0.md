# ТЗ v0.4.0 — Бэкапы базы (.dt)

## Цель

Реализовать выгрузку информационной базы в файл `.dt` и восстановление 
базы из `.dt`. Это базовый инструмент бэкапа и переноса баз 1С.

## Область применения

- Резервное копирование базы перед обновлениями.
- Перенос базы между серверами (через `.dt`).
- Создание «эталонной» копии базы для тестов.
- Восстановление базы из бэкапа.

## Архитектура

    scripts/actions/
    ├── dump_dt.py        # dump-dt — выгрузка базы в .dt
    └── restore_dt.py     # restore-dt — восстановление из .dt

## Стиль команд

Симметрия с существующими командами:

| Команда | Вход | Выход |
|---|---|---|
| `dump-config` | База + `--to <каталог>` | XML конфигурации |
| `dump-cf` | База + `--to <файл.cf>` | `.cf` |
| `dump-epf` | База + `--epf <файл.epf>` | XML обработки |
| **`dump-dt`** | База + `--to <файл.dt>` | **`.dt` база** |
| **`restore-dt`** | База + `--from <файл.dt>` | **База восстановлена** |

**Ключевое отличие:** `dump-dt` **выгружает базу**, `restore-dt` **восстанавливает базу**. 
`--ib` — целевая база (куда восстанавливать / откуда выгружать).

## Функциональные требования

### F-1. dump-dt

    onec-ops dump-dt --to <файл.dt>

Ключи 1С:

    DESIGNER /F <ib> /DisableStartupDialogs /DumpIB <файл.dt>

Поведение:
- `--ib` — источник (что выгружаем).
- `--to` — путь к выходному `.dt`.
- Создать родительский каталог, если нет.
- Если файл существует — WARNING (перезапись).

Валидация:
- `--ib` содержит `1Cv8.1CD`.
- Родительский каталог `--to` доступен для записи.
- Расширение `--to` — `.dt` (по желанию, WARNING если другое).

path_args: `("to",)`.

### F-2. restore-dt

    onec-ops restore-dt --from <файл.dt> [--force]

Ключи 1С:

    DESIGNER /F <ib> /DisableStartupDialogs /RestoreIB <файл.dt>

Поведение:
- `--ib` — целевая база (куда восстанавливать).
- `--from` — путь к `.dt`-файлу.
- **База должна существовать** (пустая или с данными).
- С `--force` — восстановить в существующую базу (перезапишет данные).

Валидация:
- `--ib` содержит `1Cv8.1CD` (база должна быть создана).
- `--from` существует, непустой.
- Расширение `--from` — `.dt`.

**Безопасность:**
- Без `--force` — если база **не пустая** (есть данные или конфигурация), 
  требуется подтверждение (как в `create-ib --force`).
- С `--force` — WARNING и восстановление.

path_args: `("from_",)`.

### F-3. Общие требования

- Все пути — абсолютные (resolve в `path_args`).
- `--dry-run` работает для обоих действий.
- Таймаут 600 с (наследуется от runner).
- Логирование: команда, stdout, stderr, код возврата, длительность.
- Безопасность: `restore-dt` требует подтверждения (как `create-ib --force`).

## Критерии приёмки

- AC-1. `onec-ops dump-dt --to <файл.dt> --ib <ib>` создаёт `.dt`.
- AC-2. `onec-ops restore-dt --from <файл.dt> --ib <ib>` восстанавливает 
  базу.
- AC-3. Round-trip: `dump-dt → restore-dt → dump-dt` — идентичные `.dt`.
- AC-4. `--dry-run` показывает команду.
- AC-5. `restore-dt` требует подтверждения (без `--force`).
- AC-6. `pytest -v` зелёный.
- AC-7. Skill обновлён: 2 новые команды.

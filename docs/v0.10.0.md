# v0.10.0 — Запуск обработки без окна (run-epf)

## Цель

По истории сессий агентов в проектах с 1С код на тестовой базе (проверки данных,
заполнение, прогон расширения на заглушке) выполняли через
`1cv8 ENTERPRISE /Execute`, вызывая платформу напрямую. `open-enterprise --execute`
для этого не подходит: ему нужен реальный `DISPLAY`, он не выдаёт результат и
не объясняет, почему клиент завис.

## Команда

    onec-ops --ib IB [--ib-user NAME] run-epf --epf file.epf [--param STRING]

- `ENTERPRISE /F <ib> [/N /P] /DisableStartupDialogs /DisableStartupMessages
  /Execute <абсолютный путь> [/C <параметр>] /Out <временный файл>`.
- Окружение как у пакетных команд: Windows и Linux с `DISPLAY` — напрямую,
  Linux без `DISPLAY` — `xvfb-run`. Отдельной проверки дисплея нет.
- `--param` (синоним `--c`, как у `open-enterprise`) → `/C`, в обработке
  `ПараметрЗапуска`. Пустая строка передаётся.
- Ждёт завершения клиента. Обработка сама вызывает `ЗавершитьРаботуСистемы(Ложь)`.
- Сообщения из `/Out` → stdout. Код возврата 1С при штатном завершении всегда 0,
  поэтому успех или ошибку обработка сообщает текстом.
- Таймаут по умолчанию 120 с вместо 600: зависание на окне — частый исход,
  ждать его 10 минут незачем. `Action.default_timeout`, явный `--timeout` важнее.
- Только `.epf`.

## Ошибки

Клиент без экрана не может ответить ни на одно окно. Проверено на 1С 8.5.1.1343:

| Ситуация | Что делает 1С |
| --- | --- |
| База без пользователей или у пользователя включена защита от опасных действий | Окно «Предупреждение безопасности», клиент ждёт |
| Исключение в коде обработки | Окно с текстом ошибки, клиент ждёт; запись `E` в журнале регистрации |
| Нет `ЗавершитьРаботуСистемы` | Форма остаётся открытой |

По таймауту `run-epf` (`on_failed`) дополняет ошибку:

- сообщениями `/Out`, которые обработка успела вывести (их уже читает `runner`);
- подсказкой о трёх причинах выше;
- ошибками журнала регистрации (`lib/eventlog.read_errors`): записи важности `E`
  в `1Cv8Log/*.lgp` не раньше времени запуска, не больше пяти. Время в журнале
  местное. Журнал SQLite (`.lgd`) не читается, сбой чтения журнала не ошибка.

Защиту от опасных действий команда не отключает и окно не нажимает: это решение
администратора базы. Документация говорит снять флажок «Защита от опасных
действий» у тестового пользователя в Конфигураторе. Параметр платформы
`DisableUnsafeActionProtection` в `conf.cfg` не упоминается как способ для агента.

## Проверка

- Тесты: аргументы, `--c`, порядок ключей и `/N`, вывод в stdout, таймаут по
  умолчанию и явный, 600 у других команд, подсказка и журнал при таймауте,
  удаление `/Out` при ошибке, dry-run, чтение журнала (старые файлы, лимит).
  639 тестов, покрытие 98%.
- Linux, 1С 8.5.1.1343, без `DISPLAY` (через `xvfb-run`), временная база с
  пользователем без защиты от опасных действий:
  - шаблон из `workflows.md`, `--param 42` → stdout «ok 42, пользователей: 1», код 0, ~2 с;
  - исключение внутри `Попытка` → stdout «ОШИБКА: …», код 0;
  - исключение без `Попытка`, `--timeout 20` → код 1, в ошибке сообщение
    обработки, подсказка и текст исключения с номером строки из журнала;
  - база без пользователей → код 1 по таймауту с подсказкой (висело окно
    «Предупреждение безопасности», проверено снимком экрана Xvfb);
  - после таймаута процессов 1С не осталось.
- Не проверено: Linux с `DISPLAY` (окно на экране пользователя), Windows.

## Проверка на Windows

1. `onec-ops create-ib --type file --path C:\Temp\runepf`, загрузить в неё
   конфигурацию с пользователем без защиты от опасных действий (или создать
   пользователя в Конфигураторе и снять флажок).
2. Собрать обработку по шаблону из `references/workflows.md` (`load-epf`).
3. `onec-ops --ib C:\Temp\runepf --ib-user Тест run-epf --epf C:\Temp\Проверка.epf --param 42`
   — в stdout «ok 42», код 0, окно клиента закрывается само.
4. То же без `--ib-user` в базе без пользователей и с `--timeout 20` — код 1 и
   подсказка про «Предупреждение безопасности».

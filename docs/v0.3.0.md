# ТЗ v0.3.0 — Внешние обработки и отчёты (.epf / .erf)

## Цель

Реализовать сборку и разборку внешних обработок (`.epf`) и отчётов 
(`.erf`) в формате XML. Это позволит версионировать исходники 
обработок и отчётов в Git и собирать их для использования в 1С.

## Область применения

- Разработка обработок и отчётов: версионирование исходников в Git.
- Сборка `.epf` / `.erf` из XML-выгрузки.
- Разборка `.epf` / `.erf` в XML для анализа и правки.

## Архитектура

    scripts/actions/
    ├── dump_epf.py       # dump-epf — разборка .epf/.erf в XML
    └── load_epf.py       # load-epf — сборка .epf/.erf из XML

## Стиль команд

Симметрия с существующими командами:

| Команда | Вход | Выход |
|---|---|---|
| `dump-config` | База + `--to <каталог>` | XML конфигурации |
| `dump-cf` | База + `--to <файл.cf>` | `.cf` |
| **`dump-epf`** | База + `--epf <файл.epf\|erf>` | **XML в `--to <каталог>`** |
| `load-config` | База + `--from <каталог>` | Конфигурация в базе |
| `load-cf` | База + `--from <файл.cf>` | Конфигурация в базе |
| **`load-epf`** | База + `--root <файл.xml>` | **`.epf\|erf` в `--epf`** |

**Ключевое отличие:** у `.epf` / `.erf` два пути — XML и файл обработки. 
Поэтому используются `--epf` (для файла) и `--to` / `--root` (для XML).

## Функциональные требования

### F-1. dump-epf

    onec-ops dump-epf --epf <файл.epf|erf> --to <каталог.xml>

Ключи 1С:

    DESIGNER /F <ib> /DisableStartupDialogs 
      /DumpExternalDataProcessorOrReportToFiles <каталог> <файл.epf|erf>

Поведение:
- `--epf` — путь к `.epf` или `.erf` (вход).
- `--to` — каталог для XML-выгрузки (выход).
- Создать каталог `--to`, если нет.
- Если каталог непустой — WARNING.

Валидация:
- `--ib` содержит `1Cv8.1CD`.
- `--epf` существует и непустой.
- Расширение `--epf` — `.epf` или `.erf` (case-insensitive).

path_args: `("epf", "to")`.

### F-2. load-epf

    onec-ops load-epf --root <файл.xml> --epf <файл.epf|erf>

Ключи 1С:

    DESIGNER /F <ib> /DisableStartupDialogs 
      /LoadExternalDataProcessorOrReportFromFiles <root.xml> <файл.epf|erf>

Поведение:
- `--root` — корневой XML-файл (вход).
- `--epf` — выходной `.epf` или `.erf`.
- Создать родительский каталог для `--epf`, если нет.

Валидация:
- `--ib` содержит `1Cv8.1CD`.
- `--root` существует и непустой.
- `--root` имеет расширение `.xml`.
- Расширение `--epf` — `.epf` или `.erf` (по желанию).

path_args: `("root", "epf")`.

### F-3. Общие требования

- Все пути — абсолютные (resolve в `path_args`).
- `--dry-run` работает для обоих действий.
- Таймаут 600 с (наследуется от runner).
- Логирование: команда, stdout, stderr, код возврата, длительность.
- Единый API для `.epf` и `.erf`: ключи 1С одинаковые, различие 
  только в расширении файла.

## Критерии приёмки

- AC-1. `onec-ops dump-epf --epf <файл.epf> --to <каталог> --ib <ib>` 
  создаёт XML-выгрузку.
- AC-2. `onec-ops load-epf --root <корневой.xml> --epf <out.epf> --ib <ib>` 
  создаёт `.epf`.
- AC-3. Round-trip: `dump-epf → load-epf → dump-epf` даёт 
  идентичные XML.
- AC-4. Работает с `.erf` (отчёты) через те же команды.
- AC-5. `--dry-run` показывает команду.
- AC-6. `pytest -v` зелёный.
- AC-7. Skill обновлён.
- AC-8. README, CHANGELOG обновлены.

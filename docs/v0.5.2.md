# ТЗ v0.5.2 — Сообщения 1С об ошибках (`/Out`)

## Цель

Показывать пользователю CLI настоящую причину ошибки пакетной 
операции 1С вместо голого кода возврата.

## Проблема

Сейчас при любой ошибке пакетной операции пользователь видит:

    1С завершилась с ненулевым кодом: 1

У `1cv8 DESIGNER` и `1cv8 CREATEINFOBASE` stdout и stderr пустые. 
Текст ошибки 1С пишет только в файл, указанный ключом `/Out <файл>`, 
а `run_1c` этот ключ не передаёт. Например, повторный `repo-add-user` 
с тем же именем падает с кодом 1, а сообщение 
«Пользователь хранилища конфигурации с именем '…' уже существует» 
видно, только если запустить 1cv8 вручную с `/Out`.

## Область применения

- `scripts/lib/runner.py` — функция `run_1c`.
- Все пакетные команды (`create-ib`, `dump-*`, `load-*`, `repo-*`, 
  `restore-dt`), которые идут через `run_1c`.
- `run_1c_popen` и GUI-запуски (`open-designer`, `open-enterprise`) 
  не меняются.

## Функциональные требования

### F-1. Ключ `/Out` для пакетных команд

Если первый аргумент — `DESIGNER` или `CREATEINFOBASE`, контекст 
не GUI (`requires_gui=False`) и в аргументах ещё нет `/Out` 
(без учёта регистра), `run_1c` создаёт временный файл и добавляет 
в конец команды:

    /Out <временный файл>

Если `/Out` уже передан, утилита ничего не добавляет, но читает 
указанный файл (и не удаляет его).

При `--dry-run` временный файл не создаётся, `/Out` в команде нет.

### F-2. Чтение файла

После завершения 1С (в том числе по таймауту) файл читается 
в кодировке `utf-8-sig` (1С пишет UTF-8 с BOM), недекодируемые 
байты заменяются. Пустой или отсутствующий файл — не ошибка.

- Непустое содержимое пишется в журнал (`Сообщения 1С (/Out): …`).
- При ненулевом коде содержимое добавляется в сообщение `OneCFailed`:

      1С завершилась с ненулевым кодом: 1
      Пользователь хранилища конфигурации с именем 'user2' уже существует

- При таймауте содержимое добавляется к сообщению о таймауте.

### F-3. Удаление временного файла

Временный файл удаляется всегда (успех, ошибка, таймаут, 
исключение до запуска). Файл, переданный пользователем, не удаляется.

## Тесты

### tests/test_runner.py
- `/Out` добавляется для `DESIGNER` и `CREATEINFOBASE`.
- `/Out` не добавляется для GUI-контекста, dry-run и если уже передан.
- Содержимое файла (с BOM) попадает в журнал и в `OneCFailed`.
- Пустой файл — сообщение без лишних строк.
- Таймаут — содержимое в сообщении.
- Временный файл удалён после успеха, ошибки и таймаута.

### Тесты действий
- Тесты, сравнивающие хвост команды (`call_args.args[0][-len(expected):]`), 
  учитывают `/Out <файл>` в конце.

## Критерии приёмки

- AC-1. Повторный `repo-add-user` с тем же именем на реальной 1С 
  выводит в CLI «Пользователь хранилища конфигурации с именем '…' 
  уже существует».
  (До слияния v0.5.1 — эквивалентная ошибка любой пакетной команды, 
  например `repo-create` в существующее хранилище.)
- AC-2. Успешная пакетная команда работает как раньше, 
  временный файл не остаётся.
- AC-3. `pytest` зелёный, покрытие не ниже 96%.
- AC-4. `ruff check scripts tests` чистый.
- AC-5. `references/troubleshooting.md` описывает, где искать 
  сообщения 1С.

## Что вне scope v0.5.2

- Ключ `/DumpResult` (код результата в файл).
- Сообщения GUI-запусков (`open-designer`, `open-enterprise`).
- Перевод/разбор текстов 1С — выводятся как есть.

# ТЗ v0.5.3 — Пользователь ИБ для пакетных команд

## Цель

Дать пакетным командам возможность входить в ИБ под пользователем 
(`/N`, `/P`). Сейчас пользователя ИБ передают только GUI-команды 
(`open-designer`, `open-enterprise`), а `dump-config`, `dump-cf` и 
остальные работают только с ИБ без списка пользователей.

## Проблема

    onec-ops --ib ./base dump-cf --to ./base.cf --user Администратор
    onec-ops: error: unrecognized arguments: --user Администратор

Если в базе есть пользователи, пакетная команда не может пройти 
аутентификацию. Обойти это через `onec-ops` нельзя.

## Область применения

- Все команды с `--ib` (`requires_ib = True`): `dump-config`, 
  `load-config`, `dump-cf`, `load-cf`, `dump-epf`, `load-epf`, 
  `dump-dt`, `restore-dt`, `repo-*`, `open-designer`, `open-enterprise`.
- `create-ib` не затрагивается: у новой базы нет пользователей.

## Архитектура

    scripts/onec_ops.py      # общие параметры --ib-user / --ib-password,
                             # переменные окружения
    scripts/actions/base.py  # Action.ib_auth_args(), Action.command_args()
    scripts/actions/open_designer.py, open_enterprise.py
                             # --user / --password — устаревшие синонимы

## Функциональные требования

### F-1. Общие параметры

    onec-ops --ib <путь> --ib-user <имя> [--ib-password <пароль>] <команда> ...
    onec-ops <команда> --ib <путь> --ib-user <имя> [--ib-password <пароль>] ...

- `--ib-user`, `--ib-password` добавляются в `_add_common_arguments` 
  рядом с `--ib`: работают и до, и после имени команды.
- Имена выбраны с префиксом `ib-`, потому что `--user` / `--password` 
  у `repo-create` и `repo-add-user` уже означают пользователя хранилища.

### F-2. Переменные окружения

- `ONEC_OPS_IB_USER`, `ONEC_OPS_IB_PASSWORD` — по аналогии 
  с `ONEC_OPS_PLATFORM`.
- Приоритет: параметр CLI → переменная окружения.
- Пароль через окружение не попадает в историю shell и список 
  процессов `onec-ops` (рекомендуемый способ для CI и агентов).
- В TOML-конфиг учётные данные не читаются (секреты в файлах — вне scope).

### F-3. Ключи 1С

Для действий с `requires_ib` сразу после `/F <ib>` вставляется:

    /N <имя> [/P <пароль>]

- Без пользователя (ни CLI, ни окружение) — ключи не добавляются, 
  поведение как сейчас.
- Пустой пароль (`--ib-password ""` или пароль не задан) — только `/N`.
- `--ib-password` без `--ib-user` — ошибка `OneCOpsError` 
  («--ib-password требует --ib-user»).
- Вставка делается в одном месте: `Action.command_args(ns, ctx)` = 
  `build_1c_args()` + `ib_auth_args()`. Её вызывают `main()` для пакетных 
  команд и `pre_run()` GUI-команд. Отдельные действия `/N` / `/P` 
  сами не собирают.
- Пароль маскируется в журнале (`/P` уже в `_PASSWORD_OPTIONS`).

### F-4. GUI-команды: совместимость

- `open-designer` / `open-enterprise` принимают и `--ib-user` / 
  `--ib-password`, и прежние `--user` / `--password`.
- Прежние параметры — синонимы; в справке помечены как устаревшие. 
  WARNING в журнал при использовании.
- Если заданы оба варианта с разными значениями — ошибка.

### F-5. create-ib

- `--ib-user` / `--ib-password` (CLI) с `create-ib` — ошибка 
  («у новой ИБ нет пользователей»).
- Переменные окружения для `create-ib` игнорируются молча 
  (чтобы CI с общим окружением не ломался).

### F-6. Dry-run

- Показывает `/N <имя>` и `/P ***`.

## Тесты

### tests/test_ib_auth.py
- `ib_auth_args`: нет пользователя → `[]`.
- Пользователь без пароля → `["/N", имя]`.
- Пользователь и пароль → `["/N", имя, "/P", пароль]`.
- Пароль без пользователя → `OneCOpsError`.
- Окружение: `ONEC_OPS_IB_USER` / `ONEC_OPS_IB_PASSWORD` подхватываются; 
  CLI перекрывает окружение.
- `command_args` вставляет ключи сразу после `/F <ib>`.

### tests/test_cli_smoke.py (или отдельный параметризованный тест)
- Для каждого действия с `requires_ib`: `--ib-user admin --ib-password secret` 
  → в команде `/N admin /P secret`, в журнале `secret` нет, есть `***`.
- Параметры работают и до, и после имени команды.
- `create-ib --ib-user x` → ошибка; окружение для `create-ib` не мешает.

### tests/test_open_designer.py, tests/test_open_enterprise.py
- `--user` / `--password` по-прежнему работают (+ WARNING).
- `--ib-user` работает.
- Оба варианта с разными значениями → ошибка.

## Критерии приёмки

- AC-1. Подготовить тестовую ИБ с пользователем и паролем 
  (Конфигуратор → Администрирование → Пользователи; например, 
  `inputs/base-auth`, пользователь «Администратор» с паролем).
- AC-2. Без учётных данных пакетная команда (`dump-cf`) на этой ИБ 
  завершается с кодом 1, текст 1С (из `/Out`, v0.5.2) объясняет 
  причину. Зафиксировать реальный текст в troubleshooting. Проверить, 
  что команда не висит до таймаута.
- AC-3. `onec-ops --ib inputs/base-auth --ib-user Администратор 
  --ib-password <пароль> dump-cf --to /tmp/base.cf` — код 0, `.cf` создан.
- AC-4. То же через `ONEC_OPS_IB_USER` / `ONEC_OPS_IB_PASSWORD`.
- AC-5. Неверный пароль → код 1 и текст ошибки 1С.
- AC-6. `dump-config` и `repo-update` на ИБ с пользователем проходят.
- AC-7. Пароль не виден в журнале ни в одном сценарии.
- AC-8. `pytest` зелёный, покрытие не ниже 97%; `ruff check scripts tests` 
  чистый.
- AC-9. Skill (раздел «Пользователь ИБ», таблица команд, ограничения), 
  README, `references/commands.md`, troubleshooting, CHANGELOG обновлены.

## Что вне scope v0.5.3

- Аутентификация ОС (`/WA+`, `/WA-`) и OpenID.
- Чтение учётных данных из TOML-конфига или менеджера секретов.
- Создание и изменение пользователей ИБ.
- Удаление `--user` / `--password` у GUI-команд (только пометка 
  «устарело»; удаление — не раньше v1.0.0).

## Открытые вопросы (проверить на реальной 1С)

- Что делает пакетный `DESIGNER` с `/DisableStartupDialogs` на ИБ 
  с пользователями без `/N`: ошибка сразу или ожидание до таймаута.
- Нужен ли `/WA-`, чтобы 1С не пыталась войти через пользователя ОС, 
  когда задан `/N`.

# ТЗ v0.8.1 — Патч: зависшие процессы, выбор платформы, документация

## Цель

Исправить находки проверки после v0.7.0 и v0.8.0.

## Проблемы

1. **Зависшие процессы после таймаута.** Без `DISPLAY` 1С запускается как 
   `xvfb-run … 1cv8`. При `--timeout` `subprocess.run` убивает только 
   прямого потомка (`xvfb-run`); `1cv8` и `Xvfb` продолжают работать. 
   Воспроизведено: после таймаута остались `Xvfb :99` и процесс платформы. 
   Зависший `1cv8` держит ИБ заблокированной — следующие команды падают. 
   Затрагивает CI, Docker и sandbox агентов. То же при Ctrl+C.
2. **Выбор платформы без тестов.** Порядок `--platform` → 
   `ONEC_OPS_PLATFORM` → ключ `platform` в TOML → путь по умолчанию описан 
   в Skill (v0.8.0), но `scripts/lib/config.py` покрыт на 73%.
3. **Устаревшая ссылка:** README и `references/commands.md` обещают 
   обновления `.cfu` в несуществующем релизе v0.2.4.

## Функциональные требования

### F-1. Группа процессов

- `run_1c` запускает 1С через `_execute(command, timeout=…)` — 
  `subprocess.Popen` с `start_new_session=True` (POSIX): `xvfb-run`, 
  `Xvfb` и `1cv8` оказываются в одной новой группе процессов.
- При таймауте и при любом прерывании (`KeyboardInterrupt` и др.) — 
  `os.killpg(pid, SIGTERM)` для всей группы, до 5 с на завершение, затем 
  `SIGKILL` оставшимся; ожидание завершения прямого потомка; исключение пробрасывается дальше (поведение 
  `OneCFailed` по таймауту и код 130 по Ctrl+C не меняются).
- Windows: `process.kill()` (Xvfb там не используется, `1cv8.exe` — 
  прямой потомок).
- `run_1c_popen` (`--no-wait`) не меняется — окно должно жить после выхода.
- Сигнатура результата прежняя (`OneCCompletedProcess`, `out_text`).

### F-2. Тесты выбора платформы

`tests/test_config.py`:
- `resolve_platform`: CLI важнее окружения и конфига; окружение важнее 
  конфига; конфиг важнее значения по умолчанию; значения по умолчанию 
  для Linux и Windows.
- `load_config`: нет файла → `{}`; явный путь; путь по умолчанию 
  через `user_config_dir`.

### F-3. Документация

- Убрать «запланирована на v0.2.4» из README и `references/commands.md`: 
  `.cfu` не поддерживается и не запланирован.
- troubleshooting, раздел «Таймаут»: процессы 1С и Xvfb завершаются.

## Тесты

- Моки запуска 1С переводятся с `subprocess.run` на `scripts.lib.runner._execute` 
  (ldd и xdpyinfo по-прежнему через `subprocess.run`).
- `tests/test_runner.py`: реальный дочерний скрипт с внуком; после таймаута 
  внук завершён (POSIX); то же при `KeyboardInterrupt`; успешный запуск 
  возвращает stdout, stderr, код.

## Критерии приёмки

- AC-1. Сценарий воспроизведения (поддельная платформа `sleep`, без 
  `DISPLAY`, `--timeout 2`): после ошибки нет ни процесса платформы, ни `Xvfb`.
- AC-2. Ctrl+C во время работы 1С — код 130, процессов не остаётся.
- AC-3. Сквозной прогон команд на реальной 1С — без изменений.
- AC-4. `pytest` зелёный, покрытие не ниже 97%, `config.py` — 100%; 
  `ruff check` чистый.

## Вне scope

- Завершение дерева процессов на Windows (`taskkill /T`).
- `ruff format`, версия пакета, CI на Windows — v0.9.0.

## Результаты

- AC-1: поддельная платформа (`exec sleep`), без `DISPLAY`, `--timeout 2` — 
  код 1, процессов платформы и `Xvfb` не осталось. Тест на реальных 
  процессах подтверждает: со старым `subprocess.run` «внук» выживает.
- AC-2: SIGINT процессу `onec-ops` во время работы под `xvfb-run` — 
  код 130, «Работа прервана пользователем», процессов не осталось.
- AC-3: сквозной прогон 22 команд на реальной 1С (8.5.1.1343), в том числе 
  `dump-cf` без `DISPLAY` через `xvfb-run` — все код 0, после успешного 
  запуска в `/tmp` ничего не остаётся.
- AC-4: 479 тестов, покрытие 98% (`runner.py` 99%, `config.py` 100%), 
  `ruff check` чистый.

## Найдено при реализации

- **SIGKILL оставлял lock-файлы Xvfb** (`/tmp/.X99-lock`): `xvfb-run -a` 
  брал следующий номер дисплея, файлы копились. Сделано мягкое завершение: 
  SIGTERM (Xvfb удаляет свой lock), через 5 с SIGKILL; тест с потомком, 
  игнорирующим SIGTERM.
- **`OSError` при запуске платформы** выводился трейсбеком; теперь 
  `OneCFailed` «Не удалось запустить 1С: …», как в `run_1c_popen`.

## Известные ограничения

- После прерванного запуска остаётся пустой каталог `/tmp/xvfb-run.*`: 
  `xvfb-run`, получив сигнал, не выполняет свою очистку. Безвреден.
- Windows: завершается только `1cv8.exe` (Xvfb не используется).

# ТЗ v0.8.0 — Полировка Skill

## Цель

Привести Agent Skill `onec-ops` в соответствие с утилитой после 
v0.2.x–v0.6.0: агент должен находить навык для любой операции, 
которую умеет `onec-ops`, выполнять её безопасно и работать одинаково 
в Claude Code и Codex — в том числе когда навык скопирован отдельно 
от репозитория.

## Проблемы

1. **`description` неверный и узкий:** обещает «клиент-серверные» ИБ 
   (не поддержаны) и упоминает только создание базы. По `description` 
   агент решает, вызывать ли навык, — для выгрузки `.cf`, `.dt`, 
   хранилища и расширений навык может не сработать.
2. **Устаревшие ограничения:** «клиент-серверная ИБ — v0.1.1», 
   «`.cfu` — v0.2.4» (таких релизов нет; актуально v0.3.1, `.cfu` 
   не запланирован).
3. **Ссылки наружу пакета навыка:** `SKILL.md` ссылается на `roadmap.md`, 
   `README.md`, `docs/`. При установке копированием 
   (`~/.codex/skills/onec-ops/`: `SKILL.md`, `agents/`, `references/`) 
   эти ссылки битые.
4. **Неполная таблица команд:** у `dump-cf`, `load-cf`, `dump-epf`, 
   `load-epf` в примерах нет `--ib`, хотя он обязателен.
5. **Нет правил безопасности для агента:** какие команды разрушают данные 
   и когда можно передавать `--yes` / `--force`.
6. **Нет типовых сценариев:** агент собирает цепочки команд сам 
   (выгрузка в git, бэкап перед загрузкой, вторая база в хранилище).
7. **Установленная копия в Codex устаревает молча:** 
   `~/.codex/skills/onec-ops/` скопирован в v0.1.0 и не обновлялся.
8. **Нет проверки дрейфа:** новая команда в CLI может не попасть 
   в `SKILL.md` / `references/commands.md`.

## Пакет навыка

Навык = три пути, которые копируются вместе:

    SKILL.md                    # точка входа, ≤ 250 строк
    agents/openai.yaml          # метаданные Codex
    references/
    ├── commands.md             # все команды: синтаксис, параметры, поведение
    ├── workflows.md            # НОВОЕ: типовые сценарии
    └── troubleshooting.md      # ошибки и диагностика

Всё, на что ссылается `SKILL.md`, лежит внутри пакета. `README.md`, 
`roadmap.md`, `docs/` — документация репозитория, не навыка.

## Функциональные требования

### F-1. description

- Третье лицо, «что делает» + «когда использовать», до 1024 символов 
  (ограничение Claude Code и Codex).
- Перечисляет группы операций: создание файловой ИБ; конфигурация 
  и расширения в XML / `.cf` / `.cfe`; список, проверка, удаление 
  расширений; обработки `.epf` / `.erf`; бэкап `.dt`; файловое 
  хранилище; открытие Конфигуратора и клиента.
- Ключевые слова, по которым пользователь формулирует задачу: 
  «выгрузить конфигурацию», «бэкап базы», «хранилище», «расширение», 
  «обработка», «Конфигуратор».
- Явное «не для»: написание кода 1С, клиент-серверные базы.

### F-2. Структура SKILL.md

1. Назначение и границы (когда использовать / когда нет).
2. **Правила безопасности** (новое):
   - разрушающие команды: `create-ib --force`, `restore-dt`, `load-config`, 
     `load-cf`, `delete-extension`, `repo-bind --force` — перед запуском 
     сказать пользователю, что будет перезаписано, и получить согласие;
   - `--yes` и `--force --yes` — только по явной просьбе пользователя;
   - перед разрушающей командой на рабочей базе предложить `dump-dt`;
   - сначала `--dry-run`, если не уверен в аргументах;
   - пароли не повторять в ответах; не подбирать учётные данные.
3. Дисплей и запреты (`xvfb-run`, `DISPLAY`) — без изменений по смыслу.
4. Таблица всех команд — у каждой команды с ИБ указан `--ib`.
5. Общие параметры и пользователь ИБ.
6. Результат и коды возврата: 0 — успех; 1 — ошибка, текст 1С после 
   строки с кодом; stdout — только у `list-extensions`.
7. Краткие разделы по группам (GUI, хранилище, расширения) — правила, 
   которые агент иначе нарушит.
8. Типовые сценарии — 3–4 коротких, остальное в `references/workflows.md`.
9. Частые ошибки (таблица).
10. Ограничения — актуальные на v0.8.0.
11. Ссылки — только на `references/`.

### F-3. references/workflows.md

Сценарии с готовыми цепочками команд:

- выгрузка конфигурации и расширений в XML для git;
- бэкап `.dt` перед загрузкой `.cf` / XML и откат;
- загрузка расширения с проверкой (`load-cf` → `check-extension`);
- вторая база в хранилище (`repo-add-user` → `repo-bind`);
- сборка обработки из XML и запуск в клиенте;
- работа с базой, где есть пользователи (через переменные окружения);
- подготовка тестовой базы в CI (`create-ib` → `load-cf` → `--yes`).

### F-4. references/commands.md

- Оглавление со ссылками на разделы всех команд.
- Раздел «Общие параметры» (сейчас разбросаны).
- Раздел «Коды возврата и вывод».

### F-5. references/troubleshooting.md

- Оглавление.
- Новые разделы: платформа не найдена (`--platform`, 
  `ONEC_OPS_PLATFORM`, конфиг); нет `DISPLAY` и `xvfb-run`; таймаут; 
  тонкий клиент `1cv8c`; GUI-команды без дисплея; подтверждение без TTY 
  (`restore-dt`, `delete-extension`, `create-ib --force`); 
  «Не найден объект…» в `check-extension`.

### F-6. Установка навыка

README, раздел «Agent Skill» (вместо «Использование с Codex»):

- **Claude Code, проект:** `.claude/skills/onec-ops/SKILL.md` → 
  симлинк на корневой `SKILL.md` (так устроено в репозитории).
- **Claude Code, глобально:** копирование пакета в 
  `~/.claude/skills/onec-ops/`.
- **Codex:** копирование пакета в `~/.codex/skills/onec-ops/` 
  (Codex не следует симлинкам); перезапуск Codex.
- **Обновление:** те же команды копирования после каждого релиза; 
  проверка — `diff -r`.
- Проверка, что навык виден агенту.
- Утилита ставится отдельно: `pipx install git+https://github.com/guesto/onec-ops.git`.

roadmap, «Технические решения → Agent Skill» — обновить под это.

### F-7. Тест дрейфа

`tests/test_skill.py`:

- frontmatter `SKILL.md`: `name: onec-ops`, `description` непустой, 
  ≤ 1024 символов, без «клиент-серверн».
- Каждое действие из `get_actions()` упомянуто в `SKILL.md` 
  и имеет раздел `## <имя>` в `references/commands.md`.
- Все относительные ссылки в `SKILL.md` и `references/*.md` ведут 
  на существующие файлы внутри пакета навыка.
- `SKILL.md` не длиннее 250 строк.

## Критерии приёмки

- AC-1. `SKILL.md` переписан по F-1, F-2; нет ссылок за пределы пакета.
- AC-2. `references/workflows.md` создан; `commands.md` и 
  `troubleshooting.md` дополнены (F-4, F-5).
- AC-3. README: установка для Claude Code и Codex, обновление навыка; 
  исправлено «pipx install onec-ops (планируется)».
- AC-4. `tests/test_skill.py` зелёный; `pytest` весь зелёный, 
  покрытие не ниже 97%; `ruff check` чистый.
- AC-5. Claude Code: навык `onec-ops` виден в проекте и на типовом 
  запросе («выгрузи конфигурацию базы в .cf») агент выбирает его 
  и строит правильную команду.
- AC-6. Codex: после копирования пакета навык виден и отвечает на тот же 
  запрос (проверяет пользователь — Codex запускается в его терминале).

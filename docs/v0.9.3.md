# v0.9.3 — Публикация в PyPI

## Цель

Утилита ставилась только из GitHub (`pipx install git+...`), а навык копировался
руками через `cp -r` в каталог каждого агента. Пакет назывался `scripts`, что
конфликтует с любым другим пакетом с таким именем в окружении и не годится для
PyPI. В `pyproject.toml` стояли заглушки автора.

Результат релиза: `pipx install onec-ops` из PyPI и `onec-ops install-skill`
вместо ручного копирования навыка.

## Пакет onec_ops

- `scripts/` переименован в `onec_ops/`, `scripts/onec_ops.py` — в `onec_ops/cli.py`.
  Точка входа: `onec-ops = "onec_ops.cli:main"`.
- Добавлен `onec_ops/__main__.py`: `python -m onec_ops`. Вставка корня репозитория
  в `sys.path` для запуска файлом удалена.
- `onec-ops --version` печатает версию установленного пакета.
- Тесты, CI, CONTRIBUTING и README переведены на `onec_ops`. Старые ТЗ
  (`docs/v0.*.md`) не меняются: они описывают состояние на момент релиза.

## Навык внутри пакета

Навык по-прежнему лежит в корне репозитория (`SKILL.md`, `references/`, `agents/`):
так его видят агенты, работающие в клоне, и на него указывают симлинки
`.claude/skills/onec-ops`. В wheel он попадает как `onec_ops/skill/`.

- Сборка переведена с setuptools на hatchling: `force-include` кладёт файлы из корня
  внутрь пакета без копий в git.
- sdist содержит `onec_ops`, `tests`, навык, README, CHANGELOG и LICENSE; `inputs/`,
  `outputs/`, `docs/` и `.github/` в пакет не попадают.
- Источник навыка для команды: `onec_ops/skill/` в установленном пакете, иначе корень
  репозитория (запуск из клона и `pip install -e`).

## Команда install-skill

    onec-ops install-skill [--agent AGENT ...] [--project DIR | --target DIR]
                           [--check] [--dry-run]

- Не входит в реестр действий 1С: не ищет платформу, не принимает `--ib`.
- Агенты: `claude` (`CLAUDE_CONFIG_DIR` или `~/.claude`), `codex` (`CODEX_HOME` или
  `~/.codex`), `kimi` (`KIMI_CODE_HOME` или `~/.kimi-code`), `agents` (`~/.agents`).
  Каталог навыка — `<дом агента>/skills/onec-ops`.
- Без `--agent` выбираются агенты, чей домашний каталог уже существует. Ни одного —
  ошибка с подсказкой.
- `--project DIR` — те же каталоги внутри проекта (`DIR/.claude/...`), переменные
  окружения не учитываются. `--target DIR` — явный каталог навыка, без `--agent`.
- Заменяются только `SKILL.md`, `references/`, `agents/`; прочие файлы в каталоге
  навыка остаются. Совпадающая копия не перезаписывается («актуально»).
- Защита: каталог с другим `name` в `SKILL.md`, непустой каталог без `SKILL.md` и
  файл вместо каталога — ошибка. Каталог из симлинков (установка для разработки)
  пропускается с предупреждением: перезапись через ссылку испортила бы репозиторий.
- `--check` печатает статус каждой копии: «актуально», «устарело», «не установлен»,
  «ссылки на репозиторий»; код 1, если есть устаревшие или неустановленные.
- `--dry-run` (до или после имени команды) показывает, куда будет установлено.

`SKILL.md` подсказывает агенту предложить `install-skill`, если CLI знает команду,
которой нет в навыке. Справочник — `references/commands.md#install-skill`.

## Публикация

- `.github/workflows/publish.yml` запускается на тег `v*.*.*`: проверяет, что тег
  совпадает с `version`, собирает sdist и wheel, `twine check --strict`, публикует
  через `pypa/gh-action-pypi-publish` с Trusted Publishing (environment `pypi`,
  `id-token: write`, без токенов в секретах).
- Разовая настройка PyPI и GitHub описана в CONTRIBUTING («Публикация в PyPI»).
  Имя `onec-ops` в PyPI на 2026-11-17 свободно.
- В `test.yml` добавлена задача `package` (Linux и Windows): сборка, `twine check`,
  `.github/scripts/check_wheel.py` (навык в wheel есть, `tests/`, `inputs/`,
  `outputs/`, `docs/`, `scripts/` нет), установка wheel в чистое окружение,
  `--version`, `install-skill --target` и `--check`.

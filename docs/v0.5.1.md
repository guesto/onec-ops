# ТЗ v0.5.1 — Пользователи хранилища конфигурации

## Цель

Добавить команду `repo-add-user` для создания пользователей файлового 
хранилища конфигурации. Снимает ограничение v0.5.0 «один пользователь 
хранилища = одна база»: для каждой базы заводится свой пользователь.

## Область применения

- Подключение нескольких баз к одному хранилищу (разработка, тесты, CI).
- Подготовка тестового хранилища с пользователями разных прав.

## Архитектура

    scripts/actions/
    └── repo_add_user.py     # repo-add-user — добавление пользователя

    scripts/lib/runner.py    # маскирование пароля нового пользователя (-Pwd)

## Функциональные требования

### F-1. repo-add-user

    onec-ops repo-add-user --storage <путь> --user <имя> --rights <права>
      [--password <пароль>] [--storage-user <админ>] 
      [--storage-password <пароль>] [--restore-deleted]

Ключи 1С:

    DESIGNER /F <ib> /DisableStartupDialogs
      /ConfigurationRepositoryF <путь>
      /ConfigurationRepositoryN <админ>
      /ConfigurationRepositoryP <пароль админа>
      /ConfigurationRepositoryAddUser
      -User <имя> [-Pwd <пароль>] -Rights <права> [-RestoreDeletedUser]

Поведение:
- `--storage` — путь к каталогу хранилища (обязательно).
- `--user` — имя нового пользователя (обязательно).
- `--password` — пароль нового пользователя (опционально).
- `--rights` — права (обязательно), одно из значений 1С:
  - `ReadOnly` — только чтение;
  - `LockObjects` — захват объектов;
  - `ManageConfigurationVersions` — управление версиями;
  - `Administration` — администрирование.
- `--storage-user` / `--storage-password` — администратор хранилища, 
  от имени которого добавляется пользователь (как в `repo-bind` / 
  `repo-update`).
- `--restore-deleted` — восстановить ранее удалённого пользователя 
  с тем же именем (`-RestoreDeletedUser`).

Валидация:
- `--ib` содержит `1Cv8.1CD`.
- `--storage` существует и является каталогом.
- `--user` непустой.
- `--rights` — одно из четырёх значений (через `choices` argparse).

Безопасность:
- Пароль после `-Pwd` маскируется в журнале команды так же, как 
  `/P` и `/ConfigurationRepositoryP` (добавить `-pwd` 
  в `_PASSWORD_OPTIONS` в `runner.py`).

## Критерии приёмки

- AC-1. `onec-ops repo-add-user --storage <путь> --user Разработчик2 
  --rights LockObjects --ib inputs/base1c` добавляет пользователя.
- AC-2. Round-trip: `repo-create` из `inputs/base1c` → 
  `repo-add-user Разработчик2` → `repo-bind` базы `inputs/base2c` 
  под `Разработчик2` без `--force` → `repo-update` для `base2c` 
  проходит. Обе базы остаются подключёнными.
- AC-3. Повторное добавление существующего пользователя падает 
  с кодом 1 и понятным сообщением из лога 1С.
- AC-4. Пароли (`/ConfigurationRepositoryP`, `-Pwd`) не попадают 
  в журнал в открытом виде.
- AC-5. `pytest -v` зелёный, покрытие не ниже 96%.
- AC-6. Skill, README и `references/commands.md` обновлены: 1 новая команда; 
  ограничение «один пользователь = одна база» дополнено ссылкой 
  на `repo-add-user`.

## Что вне scope v0.5.1

- Удаление и изменение пользователей хранилища.
- `repo-dump` (выгрузка версии в `.cf`).
- `repo-unbind` (отключение от хранилища).
- Сервер хранилища (`crserver`) и удалённые хранилища.

# ТЗ v0.8.4 — Проверка модулей, частичная выгрузка и пробелы в пути ИБ

## Цель

Закрыть три случая, из-за которых агенты вызывали `1cv8` напрямую или
пропускали шаг:

1. Новые команды `check-modules` и `check-config`.
2. Исправление `create-ib` для пути с пробелом.
3. Частичная выгрузка и загрузка XML: `dump-config` и `load-config`
   работают со списком объектов или файлов.

## Зачем

По журналам прошлых сессий (счётчики приблизительные):

| Случай | Что было |
| --- | --- |
| Проверка модулей | `/CheckModules` напрямую 19 раз в 5 проектах, `/CheckConfig` 2 раза. В `integration` проверку однажды не запустили, потому что команды нет. |
| Пробел в пути | `create-ib` падает с ошибкой «Неверные или отсутствующие параметры соединения». Базу создавали напрямую через `1cv8 CREATEINFOBASE`. |
| Частичная выгрузка | `/DumpConfigToFiles -listFile` напрямую 4 раза в `signum`, чтобы взять из УНФ один справочник или форму. |

Шаблон `templates/AGENTS.md` запрещает вызывать `1cv8` напрямую, поэтому без этих
команд агент либо нарушает правило, либо пропускает проверку.

## Поведение 1С (проверено на 8.5.1.1343, Linux)

Проверка шла на временной базе из конфигурации `inputs/base3c` и расширения
`inputs/etc1c/onec.cfe`. В модуль объекта добавлялась синтаксическая ошибка.

### Проверка

| Вызов | Конфигурация с ошибкой в модуле | Без ошибок |
| --- | --- | --- |
| `/CheckModules` без режимов | **код 0, «Синтаксических ошибок не обнаружено!»** | код 0 |
| `/CheckModules -ThinClient` | **код 0**: модуль объекта на тонком клиенте не компилируется | код 0 |
| `/CheckModules -Server` | код 101, список ошибок | код 0 |
| `/CheckModules` со всеми пятью режимами | код 101, ошибки по каждому режиму | код 0 |
| `/CheckConfig` без ключей | код 101, ошибки только режима «Сервер» | код 0 |
| `/CheckConfig -ConfigLogIntegrity` | **код 0**: модули не проверяются | код 0 |
| `/CheckConfig` с `-ConfigLogIntegrity -IncorrectReferences` и пятью режимами | код 101 | код 0, «Ошибок не обнаружено» |

Выводы:

- Код 0 без режимов ничего не доказывает. Поэтому по умолчанию команды передают
  все пять режимов: `-ThinClient -WebClient -Server -ExternalConnection
  -ThickClientOrdinaryApplication`.
- Код 101 означает «есть замечания». Обычный сбой запуска даёт код 1.
- `-ExtendedModulesCheck` даёт код 101 и на одном предупреждении «Возможно
  ошибочное свойство», хотя без этого ключа тот же модуль проходит с кодом 0.
- Несуществующее расширение даёт код 1. Рабочие `-Extension` и `-AllExtensions`
  дают код 0.
- Проверка работает и на конфигурации, ещё не применённой к базе данных.

## Функциональные требования

### F-1. check-modules

    onec-ops check-modules --ib <путь> [--mode <режим> ...] [--extended]
      [--extension <имя> | --all-extensions]

    DESIGNER /F <ib> /DisableStartupDialogs /CheckModules <режимы>
      [-ExtendedModulesCheck] [-Extension <имя> | -AllExtensions]

Значения `--mode` (можно повторять):

| Значение | Ключ 1С |
| --- | --- |
| `thin-client` | `-ThinClient` |
| `web-client` | `-WebClient` |
| `server` | `-Server` |
| `external-connection` | `-ExternalConnection` |
| `thick-client` | `-ThickClientOrdinaryApplication` |

- Без `--mode` передаются все пять режимов. Запуск вообще без режимов невозможен.
- Мобильные режимы в этот релиз не входят: они не проверялись.
- `--extended` включает `-ExtendedModulesCheck`. По умолчанию ключ выключен:
  в старом коде он находит много предупреждений и даёт код 101.
- Выбор расширения необязателен, правила те же, что у `update-db`
  (`validate_extension_target(ns, required=False)`).
- Команда поддерживает `--ib-user`, `--ib-password` и `--dry-run`.

### F-2. check-config

    onec-ops check-config --ib <путь> [--mode <режим> ...] [--extended]
      [--extension <имя> | --all-extensions]

    DESIGNER /F <ib> /DisableStartupDialogs /CheckConfig
      -ConfigLogIntegrity -IncorrectReferences <режимы>
      [-ExtendedModulesCheck] [-Extension <имя> | -AllExtensions]

- Режимы и остальные параметры те же, что в F-1.
- `-ConfigLogIntegrity` и `-IncorrectReferences` передаются всегда.
- Остальные ключи `/CheckConfig` в этот релиз не входят.

### F-3. Результат проверки

| Код 1С | Код CLI | Вывод |
| --- | --- | --- |
| 0 | 0 | INFO с текстом 1С, например «Синтаксических ошибок не обнаружено!» |
| 101 | 1 | ERROR «Найдены замечания 1С:» и текст `/Out` без разбора и обрезки |
| другой | 1 | Обычная ошибка запуска, как у остальных команд |

- Текст 1С не разбирается: сообщения бывают многострочными (`<<?>>…`).
- Сейчас `run_1c` вызывается в `main` и бросает `OneCFailed`. Нужна точка
  расширения в `Action`, чтобы проверка заменила заголовок для кода 101, а все
  остальные команды работали как раньше.

### F-4. create-ib: путь с пробелом

- Строка подключения: `File="<абсолютный путь>"`.
- Путь с двойной кавычкой отклоняется в `validate` с кодом 1 и понятным сообщением
  до создания каталога и запуска 1С.
- Остальная логика (`--force`, `--yes`, создание каталога) не меняется.

### F-5. dump-config: частичная выгрузка

    onec-ops dump-config --ib <путь> --to <каталог>
      [--object <имя> ... | --list-file <файл>] [--extension <имя>]

    DESIGNER ... /DumpConfigToFiles <каталог> -listFile <файл> [-Extension <имя>]

- `--object` можно повторять. `--object` и `--list-file` взаимно исключают друг друга.
- Для `--object` CLI сам пишет временный список (UTF-8).
- Запускать 1С нельзя, если список пуст: пустое значение `--object`, а также файл
  без непустых строк дают код 1. Иначе платформа молча выгрузит всю конфигурацию.
- С `--all-extensions` частичная выгрузка запрещена: код 1 до запуска 1С, иначе
  платформа падает.
- `--list-file` должен существовать и читаться как UTF-8, BOM и CRLF допускаются.

### F-6. load-config: частичная загрузка

    onec-ops load-config --ib <путь> --from <каталог>
      [--file <путь> ... | --list-file <файл>] [--extension <имя>] [--update-db-cfg]

    DESIGNER ... /LoadConfigFromFiles <каталог> -listFile <файл>
      [-Extension <имя>] [/UpdateDBCfg]

- Пути указываются относительно `--from`.
- `--file` можно повторять. `--file` и `--list-file` взаимно исключают друг друга.
- Пустой список и сочетание с `--all-extensions` дают код 1 до запуска 1С.
- Каждый путь должен существовать и находиться внутри `--from`, иначе код 1 с именем
  файла.
- `Configuration.xml` в `--from` при частичной загрузке не требуется.
- **`-updateConfigDumpInfo` при частичной загрузке не передаётся**, иначе 1С
  перепишет файл исходников, которого нет в списке.
- Полная загрузка не меняется, включая `-updateConfigDumpInfo`. Отдельный флаг для
  неё в этот релиз не входит.

### F-7. Временный список

- Временный файл создаётся в `pre_run`, в том числе при `--dry-run`, а содержимое
  списка пишется в журнал на уровне INFO.
- Файл удаляется в `finally` при успехе, ошибке и таймауте. Для этого нужна точка
  очистки в `Action`, которая по умолчанию ничего не делает.
- Файл `--list-file` пользователя не меняется и не удаляется.

## Архитектура

    scripts/actions/check_modules.py     # check-modules, check-config, общие режимы
    scripts/actions/dump_config.py       # --object, --list-file
    scripts/actions/load_config.py       # --file, --list-file
    scripts/actions/partial_list.py      # чтение, проверка и временный файл списка
    scripts/actions/create_ib_file.py    # кавычки в File=
    scripts/actions/base.py              # точки расширения результата и очистки
    scripts/onec_ops.py                  # вызов этих точек

## Вне этого релиза

- Чтение журнала регистрации, команда состояния базы и процессов.
- Флаг отключения `-updateConfigDumpInfo` при полной загрузке.
- Режим обычного приложения в `open-enterprise`.
- Разбор замечаний 1С и вывод в JSON.
- Изменение таймаута по умолчанию (600 с). Для больших конфигураций документация
  советует `--timeout`: в `signum` на УНФ использовали 1200 с.

## Проверка на реальной 1С

Только на временных базах и копиях `inputs/`, сам `inputs/` не меняется.

1. Ошибка в серверном модуле: `check-modules` и `check-config` дают код 1 и текст
   ошибки, после исправления код 0.
2. Только предупреждение: без `--extended` код 0, с `--extended` код 1.
3. `--extension onec`, несуществующее расширение и `--all-extensions`.
4. Выгрузка одного объекта через `--object` и `--list-file`, отказ на пустом списке.
5. Загрузка одного `.bsl` из каталога без `Configuration.xml`: `ConfigDumpInfo.xml`
   не меняется, изменение видно в базе.
6. `create-ib` в каталоге с пробелом, затем `dump-config` и `check-modules` в этой базе.
7. Журнал показывает, что при таймауте и ошибке временный файл удалён.

## Открытые вопросы

- **Windows не проверен.** `subprocess` на Windows экранирует кавычки в аргументе
  как `\"`, поэтому формат `File="..."` может там работать иначе. До релиза нужна
  проверка `create-ib` на Windows с пробелом и без него: `templates/` рассчитан в том
  числе на Windows. На этой машине Windows нет.
- **Режимы для клиентского кода.** Проверка подтвердила выводы только для серверного
  контекста. Ошибку, которая видна лишь клиентскому режиму, нужно проверить на модуле
  формы или общем клиентском модуле.

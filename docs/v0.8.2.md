# v0.8.2 — Загрузка всех расширений и ошибки TOML

## Исправлено

- `dump-config --all-extensions` создаёт подкаталог для каждого расширения.
  `load-config --all-extensions` ошибочно требовал `Configuration.xml` в общем
  корневом каталоге и отказывался принимать собственную выгрузку. Теперь эта
  проверка выполняется только для основной конфигурации.
- Ошибки чтения и разбора TOML-конфига преобразуются в `OneCOpsError`:
  CLI сообщает путь файла и причину, возвращает код 1 без Python traceback.
- Значение `platform` проверяется на строковый тип до запуска платформы.
  Числа, логические значения, массивы и таблицы отклоняются с понятной ошибкой.

## Версия пакета

В `pyproject.toml` установлена версия `0.8.2` вместо устаревшей `0.1.0.dev0`.
Публикация в PyPI и команда `--version` в этот патч не входят.

## Проверка

- 8 новых регрессионных проверок воспроизводили ошибки до исправления.
- Полный набор: 487 тестов, покрытие 98%; `config.py` и `load_config.py` — 100%.
- `ruff check .` и `git diff --check` — без ошибок.
- Реальный CLI: некорректный TOML, неверный тип `platform` и каталог вместо
  файла конфига возвращают код 1 без traceback; платформа не запускается.
- Реальная 1С 8.5.1.1343: создана отдельная тестовая база, загружена основная
  конфигурация, затем XML всех расширений с обновлением БД; расширение найдено
  через `list-extensions`, проверено через `check-extension --all-extensions`
  и повторно выгружено. XML-содержимое совпало побайтово, кроме служебного
  `ConfigDumpInfo.xml`, исключённого из сравнения.

Существующие базы и хранилища при проверке не менялись. Проверки выполнены
на Linux с Python 3.14.4; реальные GUI-операции и Windows не проверялись.

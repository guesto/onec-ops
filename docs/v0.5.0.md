# ТЗ v0.5.0 — Хранилище конфигурации (файловое)

## Цель

Реализовать базовые команды для работы с хранилищем конфигурации 
1С в файловом варианте (без сервера `crserver`).

## Область применения

- Создание локального хранилища для тестов.
- Подключение базы к хранилищу.
- Обновление конфигурации из хранилища.
- Управление пользователями хранилища (опционально).

## Архитектура

    scripts/actions/
    ├── repo_create.py       # repo-create — создание хранилища
    ├── repo_bind.py         # repo-bind — подключение базы к хранилищу
    └── repo_update.py       # repo-update — обновление из хранилища

## Функциональные требования

### F-1. repo-create

    onec-ops repo-create --storage <путь> [--user <админ>] [--password <пароль>]

Ключи 1С:

    DESIGNER /F <ib> /DisableStartupDialogs 
      /ConfigurationRepositoryCreate <путь>
      /ConfigurationRepositoryN <user>
      /ConfigurationRepositoryP <password>

Поведение:
- `--storage` — путь к каталогу хранилища (обязательно).
- `--user` — пользователь-администратор хранилища (по умолчанию «Администратор»).
- `--password` — пароль (опционально).
- Создать каталог `--storage`, если нет.

Валидация:
- `--ib` содержит `1Cv8.1CD`.
- Родительский каталог `--storage` доступен для записи.

### F-2. repo-bind

    onec-ops repo-bind --storage <путь> --storage-user <user> 
    --storage-password <pwd> [--force]

Ключи 1С:

    DESIGNER /F <ib> /DisableStartupDialogs 
      /ConfigurationRepositoryBindCfg
      /ConfigurationRepositoryF <путь>
      /ConfigurationRepositoryN <user>
      /ConfigurationRepositoryP <pwd>
      [-forceBindAlreadyBindedUser] [-forceReplaceCfg]

Поведение:
- `--storage` — путь к хранилищу.
- `--storage-user` / `--storage-password` — аутентификация хранилища.
- `--force` — перезаписать существующую конфигурацию в базе.

### F-3. repo-update

    onec-ops repo-update --storage <путь> --storage-user <user> 
    --storage-password <pwd> [--force] [--version <N>]

Ключи 1С:

    DESIGNER /F <ib> /DisableStartupDialogs 
      /ConfigurationRepositoryUpdateCfg
      /ConfigurationRepositoryF <путь>
      /ConfigurationRepositoryN <user>
      /ConfigurationRepositoryP <pwd>
      [-v <N>] [-force]

Поведение:
- `--storage` — путь к хранилищу.
- `--version` — номер версии (опционально, по умолчанию последняя).
- `--force` — получить новые объекты (если есть).

## Критерии приёмки

- AC-1. `onec-ops repo-create --storage <путь> --ib inputs/base1c` 
  создаёт хранилище.
- AC-2. `onec-ops repo-bind --storage <путь> --ib inputs/base1c` 
  подключает базу к хранилищу.
- AC-3. `onec-ops repo-update --storage <путь> --ib inputs/base1c` 
  обновляет конфигурацию.
- AC-4. Round-trip: создать хранилище → подключить базу → 
  проверить, что база «в хранилище».
- AC-5. `pytest -v` зелёный.
- AC-6. Skill обновлён: 3 новые команды.

## Ограничения

- **Один пользователь хранилища = одна база.**
  1С не разрешает подключать вторую базу к хранилищу тем же 
  пользователем. При `repo-bind --force` с `-forceBindAlreadyBindedUser` 
  происходит **перепривязка**: старая база отвязывается, новая 
  привязывается.
  
  Для нескольких баз — создавайте отдельных пользователей 
  (v0.5.1: `repo-add-user`).

- **`repo-bind` для базы-источника** (из которой создано хранилище) 
  не нужен — она подключается автоматически при `repo-create`.

- **`repo-update`** работает только для **подключённой** базы.
  Если база отвязана (после перепривязки) — падает с кодом 1.

# ТЗ v0.9.0 — CI на Windows и единые проверки кода

## Цель

Запускать тесты на Linux и Windows при каждом изменении и закрепить единые правила
кода в CI и локально. Публикация в PyPI вынесена в v0.9.1.

## Зачем

- На Windows команды `onec-ops` не запускались ни в CI, ни в ручных проверках, хотя
  Windows заявлен как поддерживаемая система, а `templates/` рассчитан в том числе на него.
- `ruff format` в CI нет, и 28 файлов ему не соответствуют.
- Порог покрытия нигде не закреплён: сейчас 98%, но падение никто не заметит.
- Переименование пакета в v0.9.1 затронет все импорты, поэтому CI на обеих системах
  должен заработать раньше него.

## Текущее состояние (проверено 2026-11-06)

| Что | Состояние |
| --- | --- |
| `.github/workflows/test.yml` | `ubuntu-latest`, Python 3.11–3.13, `ruff check`, `pytest`. Последние запуски успешны |
| Локальное окружение | Python 3.14.4, Ruff 0.16.10, 571 тест, покрытие 98% |
| Версия Ruff в `pyproject.toml` | `ruff>=0.1`, не закреплена |
| `ruff format --check` | 28 файлов требуют правки: 4 в `scripts/`, 24 в `tests/` |
| Пробное форматирование на копии | Около 590 изменённых строк, `ruff check` чист, 571 тест прошёл |
| `.pre-commit-config.yaml`, `CONTRIBUTING.md` | Нет |

Windows-ветки в `scripts/` есть (`config.py`, `platform_check.py`, `runner.py`,
`open_designer.py`, `open_enterprise.py`), но тесты проверяют их только подменой
`sys.platform` на Linux.

## Функциональные требования

### F-1. Форматирование отдельным коммитом

- Первый коммит реализации содержит только результат `ruff format` и не меняет логику.
- Его хеш добавляется в `.git-blame-ignore-revs`, чтобы `git blame` не указывал
  на форматирование.

### F-2. Матрица CI

    os: [ubuntu-latest, windows-latest]
    python-version: ["3.11", "3.12", "3.13", "3.14"]

- `fail-fast: false` сохраняется, запуск на `push` в `main` и на PR тоже.
- Добавляется запуск на `push` в `release/**`: матрицу нужно проверять до открытия PR.
  На ветке с открытым PR каждый пуш запускает CI дважды, это приемлемо.
- Шаги: установка, `ruff check scripts tests`, `ruff format --check scripts tests`,
  `pytest`, проверка запуска `onec-ops --help`.

### F-3. Тесты на настоящем Windows

- Тесты проходят на `windows-latest`. Подмена `sys.platform` остаётся для проверки
  веток другой системы.
- `skipif(sys.platform == "win32")` разрешён только для того, чего на Windows нет:
  shell-скрипты, группы процессов и `killpg` в `tests/test_runner.py`. У каждого
  пропуска указывается причина. Для всех остальных падений исправляется тест или код.
- Жёсткие пути (`/usr/bin/xvfb-run`, `/opt/1cv8`, `"/ib"`) и `chmod` проверяются по
  фактическим падениям. Массовая правка заранее не нужна.
- Настоящая ошибка в `scripts/` исправляется в этом релизе с регрессионным тестом и
  записью в CHANGELOG. Если правка большая, она выносится отдельным патчем, а тест
  временно получает `xfail(strict=True)` со ссылкой на задачу.

### F-4. Кодировка вывода

- `onec-ops --help` содержит кириллицу. На Windows вывод в канал может идти не в UTF-8.
- Если шаг `onec-ops --help` падает с `UnicodeEncodeError`, CLI настраивает потоки
  вывода так, чтобы неподдерживаемые символы не приводили к падению.
- Если шаг проходит, код не меняется. Сейчас падение только предполагается.

### F-5. Порог покрытия

    [tool.coverage.report]
    fail_under = 90

- Roadmap требует не меньше 80%. Порог 90% оставляет запас на различия систем, но
  замечает заметное падение от текущих 98%.
- Порог действует на обеих системах.

### F-6. Закреплённая версия Ruff и pre-commit

- В `dev` указывается точная версия Ruff, и `pre-commit` добавляется в зависимости.
- `.pre-commit-config.yaml` содержит `ruff-check` и `ruff-format` из
  `astral-sh/ruff-pre-commit` с той же версией. Наличие тега проверяется при реализации.
- Хуки не обязательны: CI остаётся главной проверкой, а установка `pre-commit install`
  описывается в `CONTRIBUTING.md`.

### F-7. CONTRIBUTING.md

Короткий файл на русском:

- установка окружения и запуск проверок;
- правило: проверки на реальной 1С идут только на копиях `inputs/`, сам `inputs/` не меняется;
- порядок релиза: ТЗ, ветка `release/vX.Y.Z`, проверка, PR, тег на merge-коммите;
- при новой команде обновляются `SKILL.md` и `references/commands.md`, это проверяет
  `tests/test_skill.py`;
- после обновления навык копируется вручную (до v0.9.1).

### F-8. Версия и документация

- Версия `0.9.0` в `pyproject.toml`, запись в `CHANGELOG.md`, версия и раздел
  разработки в `README.md`.
- `README.md` не обещает работу на Windows сверх проверенного.

## Вне этого релиза

- Переименование пакета `scripts`, команда `install-skill`, данные автора и публикация
  в PyPI: это v0.9.1.
- Клиент-серверная база (v0.3.1).
- `read-log`, `status`, флаг `--no-update-dump-info`, `open-enterprise --ordinary`.
- Запуск настоящей 1С в CI: платформы там нет.

## Проверка

1. CI на ветке: все 8 задач зелёные (2 системы, 4 версии Python).
2. Намеренная ошибка форматирования и падение теста дают красный CI. Проверяется на
   временной ветке, которая затем удаляется.
3. Снижение покрытия ниже порога даёт красный CI: локально через `--cov-fail-under`
   или проверкой настройки `fail_under`.
4. `pre-commit run --all-files` на чистом дереве не вносит изменений.
5. Все изменения логики из F-3 и F-4 проверены на реальной 1С под Linux, на копиях
   `inputs/`: `create-ib`, `dump-config`, `check-modules`.

## Ручная проверка на Windows

CI подтверждает только код с имитацией платформы. Как настоящая 1С разбирает
`File="..."`, он не покажет: это открытый вопрос из v0.8.4. До релиза нужен ручной прогон
на Windows с установленной 1С:

    onec-ops create-ib --type file --path "C:\Temp\onec check"
    onec-ops create-ib --type file --path C:\Temp\onec-check
    onec-ops --ib "C:\Temp\onec check" check-modules

Если база не создаётся, исправление входит в этот релиз.

## Результат первого запуска на Windows

- Упало 11 из 571 теста на всех версиях Python. Все причины в самих тестах: диск в
  абсолютном пути, `repr` путей в журнале, обратная косая в строке TOML в двойных кавычках.
- `skipif` и `xfail` не понадобились.
- F-4 подтвердился: `onec-ops --help` падал с `UnicodeEncodeError` на выводе в канал.
  Воспроизводится на Linux через `PYTHONIOENCODING=cp1252`. Исправлено: у `stdout` задан
  `errors="backslashreplace"`.
- Логи задач GitHub без входа недоступны, поэтому добавлен шаг с аннотацией упавших тестов.

## Открытые вопросы

- **Обязательность проверок.** Сделать CI обязательным для слияния можно только в настройках
  репозитория на GitHub. Это решает владелец репозитория после релиза.

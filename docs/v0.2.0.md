# ТЗ v0.2.0 — Конфигурация (XML)

## Цель

Реализовать выгрузку и загрузку конфигурации 1С в/из XML-формата.
Это ядро повседневной работы с конфигурацией — от Git-версионирования 
до миграции между базами.

## Область применения

- Выгрузка конфигурации в XML для хранения в Git.
- Загрузка конфигурации из XML (миграция, развёртывание).
- Работа с расширениями конфигурации (опционально).

## Архитектура

    scripts/actions/
    ├── dump_config.py       # dump-config — выгрузка в XML
    └── load_config.py       # load-config — загрузка из XML

Действия используют существующие `base.py`, `runner.py`, `config.py`.

## Функциональные требования

### F-1. Действие dump-config

CLI:

    onec-ops dump-config --to <каталог> [--format {hierarchical,plain}]
                         [--extension <имя>] [--all-extensions]

Ключи 1С:

    DESIGNER /F <ib> /DisableStartupDialogs
      /DumpConfigToFiles <каталог> [-Format <формат>]
      [-Extension <имя>] [-AllExtensions]

Поведение:
- `--to` обязателен. Создать каталог, если нет.
- Если каталог непустой — WARNING (перезапись).
- `--format` по умолчанию `hierarchical` (для Git).
- `--extension` и `--all-extensions` взаимоисключающие.

Валидация:
- `--ib` содержит `1Cv8.1CD` (файловая ИБ).
- `--to` доступен для записи.

### F-2. Действие load-config

CLI:

    onec-ops load-config --from <каталог> [--extension <имя>]
                         [--all-extensions] [--update-db-cfg]

Ключи 1С:

    DESIGNER /F <ib> /DisableStartupDialogs
      /LoadConfigFromFiles <каталог> [-updateConfigDumpInfo]
      [-Extension <имя>] [-AllExtensions]
      [/UpdateDBCfg]

Поведение:
- `--from` обязателен. Каталог должен существовать.
- `--update-db-cfg` (флаг) — вызвать `/UpdateDBCfg` после загрузки.
- `--extension` и `--all-extensions` взаимоисключающие.

Валидация:
- `--ib` содержит `1Cv8.1CD`.
- `--from` содержит `Configuration.xml` (для основной конфигурации).
- Для `--extension` — файл расширения присутствует.

### F-3. Общие требования

- Все пути — абсолютные (resolve в `path_args`).
- `--dry-run` работает для обоих действий.
- Таймаут 600 с (наследуется из runner).
- Логирование: команда, stdout, stderr, код возврата, длительность.

## Критерии приёмки

- AC-1. `onec-ops dump-config --to /tmp/xml --ib inputs/base1c` создаёт 
  XML-выгрузку конфигурации.
- AC-2. `onec-ops load-config --from /tmp/xml --ib inputs/base1c` 
  загружает конфигурацию.
- AC-3. Round-trip: `dump-config → load-config → dump-config` даёт 
  идентичные XML (или с минимальными служебными различиями).
- AC-4. `--dry-run` показывает команду без запуска 1С.
- AC-5. `--extension` и `--all-extensions` работают.
- AC-6. `pytest -v` зелёный.
- AC-7. Skill обновлён: разделы dump-config и load-config.
- AC-8. README обновлён.

# ТЗ v0.6.0 — Расширения: список, проверка, удаление

## Цель

Закрыть релиз v0.6.0 «Расширения». Выгрузка и загрузка расширений уже 
есть (`--extension` / `--all-extensions` в `dump-config`, `load-config`, 
`dump-cf`, `load-cf` — v0.2.0, v0.2.2). Не хватает операций, отложенных 
в roadmap как «может быть добавлено позже»:

- `list-extensions` — список расширений в ИБ;
- `check-extension` — проверка, что расширение можно применить;
- `delete-extension` — удаление расширения из ИБ.

## Область применения

- Агент или CI узнаёт, какие расширения есть в базе, перед выгрузкой 
  или загрузкой.
- Проверка совместимости расширения с конфигурацией после 
  `load-cf --extension` / обновления основной конфигурации.
- Очистка тестовой базы от расширений.

## Архитектура

    scripts/actions/
    ├── list_extensions.py   # list-extensions
    ├── check_extension.py   # check-extension
    └── delete_extension.py  # delete-extension

    scripts/lib/runner.py    # OneCCompletedProcess.out_text — текст /Out

## Ключи 1С (проверено на 8.5.1.1343)

| Операция | Ключ | Результат |
| --- | --- | --- |
| Список | `/DumpDBCfgList -AllExtensions` | имена в `/Out`, по одному в строке |
| Проверка | `/CheckCanApplyConfigurationExtensions -Extension <имя>` / `-AllExtensions` | код 0 или 1 + причины в `/Out` |
| Удаление | `/DeleteCfg -Extension <имя>` / `-AllExtensions` | код 0; несуществующее имя — код 1 |

В `/Out` могут попадать посторонние сообщения 1С (например, 
«Соединение с хранилищем конфигурации не установлено» у базы, 
подключённой к недоступному хранилищу).

## Функциональные требования

### F-1. Текст /Out в результате run_1c

- `run_1c` возвращает `OneCCompletedProcess` — наследник 
  `subprocess.CompletedProcess` с полем `out_text` (текст `/Out`, 
  без BOM, `strip()`). При dry-run `out_text = ""`.
- Остальное поведение v0.5.2 (журнал, ошибки, удаление файла) 
  не меняется.

### F-2. list-extensions

    onec-ops list-extensions --ib <путь>

    DESIGNER /F <ib> /DisableStartupDialogs /DumpDBCfgList -AllExtensions

- Печатает в **stdout** имена расширений по одному в строке 
  (журнал по-прежнему в stderr) — вывод можно разбирать скриптом.
- Из `/Out` берутся только строки-идентификаторы 1С 
  (буква или `_`, затем буквы, цифры, `_`); сообщения 1С с пробелами 
  и знаками отбрасываются.
- Нет расширений — пустой stdout, в журнале INFO «Расширений нет».
- В список попадают и загруженные, но не применённые к БД расширения 
  (проверено на 1С: `onec` на `base3c` после неудачного `/UpdateDBCfg`).
- Dry-run — команда в журнале, stdout пустой.

### F-3. check-extension

    onec-ops check-extension --ib <путь> (--extension <имя> | --all-extensions)

    DESIGNER /F <ib> /DisableStartupDialogs 
      /CheckCanApplyConfigurationExtensions (-Extension <имя> | -AllExtensions)

- Ровно один из `--extension` / `--all-extensions` (иначе ошибка).
- Код 0 — INFO «Расширение можно применить: <имя>» 
  («Все расширения можно применить»).
- Код 1 — ошибка CLI с причинами из `/Out` (v0.5.2).
- ИБ не изменяется.

### F-4. delete-extension

    onec-ops delete-extension --ib <путь> (--extension <имя> | --all-extensions) [--yes]

    DESIGNER /F <ib> /DisableStartupDialogs 
      /DeleteCfg (-Extension <имя> | -AllExtensions)

- Ровно один из `--extension` / `--all-extensions`.
- Удаление необратимо и удаляет данные объектов расширения, поэтому 
  требуется подтверждение `Y` (как в `restore-dt`): WARNING в журнал, 
  вопрос в stderr.
- `--yes` — без вопроса (CI). Без TTY и без `--yes` — ошибка 
  с подсказкой. Ответ не `Y` — «Отменено пользователем».
- Dry-run: подтверждение действует так же, 1С не запускается.
- Несуществующее расширение — код 1 и текст 1С.

### F-5. Общее

- Все три команды требуют `--ib` (`requires_ib`), поддерживают 
  `--ib-user` / `--ib-password` (v0.5.3) и dry-run.
- `--extension` с пустым именем — ошибка.

## Тесты

### tests/test_runner.py
- `out_text` заполнен содержимым `/Out` (с BOM), пустой при dry-run.

### tests/test_list_extensions.py
- build_1c_args: правильная команда.
- Разбор `/Out`: имена; посторонние сообщения отброшены; пустой вывод.
- CLI: stdout — имена, по одному в строке; dry-run — пустой stdout.

### tests/test_check_extension.py
- validate: нет выбора / оба сразу / пустое имя.
- build_1c_args: `-Extension <имя>` и `-AllExtensions`.
- CLI: код 0 → INFO; код 1 → код возврата 1 и текст `/Out`.

### tests/test_delete_extension.py
- validate: нет выбора / оба сразу / пустое имя.
- build_1c_args: `-Extension <имя>` и `-AllExtensions`.
- Подтверждение: `--yes`; ответ `Y`; другой ответ — отмена; без TTY — ошибка.
- Dry-run с `--yes` не запускает 1С.

## Критерии приёмки

На копии тестовой базы с расширением `inputs/etc1c/onec.cfe`:

- AC-1. `list-extensions` на базе без расширений — пустой stdout; 
  после `load-cf --extension onec` — `onec`.
- AC-2. `check-extension --extension onec` на совместимой базе — код 0; 
  на несовместимой — код 1 и причины 1С в выводе.
- AC-3. `delete-extension --extension onec --yes` — код 0, 
  `list-extensions` снова пуст.
- AC-4. `delete-extension --extension nosuch --yes` — код 1, 
  «расширение конфигурации с указанным именем не найдено».
- AC-5. Команды работают с `--ib-user` на базе с пользователями.
- AC-6. `pytest` зелёный, покрытие не ниже 97%; `ruff check scripts tests` 
  чистый.
- AC-7. Skill (3 новые команды), README, `references/commands.md`, 
  CHANGELOG, roadmap обновлены.

## Что вне scope v0.6.0

- Изменение свойств расширения (безопасный режим, защита от опасных 
  действий, активность) — `/ManageCfgExtensions` и т. п.
- Применение расширения без загрузки (`/UpdateDBCfg -Extension`) — 
  уже покрыто `load-cf --update-db-cfg`.
- Формат вывода JSON для `list-extensions`.

## Результаты проверки на реальной 1С (8.5.1.1343)

Копии `inputs/base1c` (с пользователем, `ONEC_OPS_IB_USER`) и `inputs/base3c`:

- AC-1: `list-extensions` → `onec` (в `inputs/base1c` расширение уже 
  загружено); после удаления — пустой stdout. На `base3c` строка 
  «Соединение с хранилищем конфигурации не установлено» отфильтрована.
- AC-2: `check-extension --extension onec` / `--all-extensions` на `base1c` → 
  код 0; на `base3c` → код 1 и причины 1С («Не найден объект 
  Справочник.Номенклатура» и др.).
- AC-3: `delete-extension --extension onec --yes` → код 0, список пуст; 
  `--all-extensions --yes` на `base3c` → код 0.
- AC-4: `--extension nosuch --yes` → код 1, «…расширение конфигурации 
  с указанным именем не найдено: nosuch».
- Без TTY и без `--yes` → ошибка с подсказкой, 1С не запускается.
- AC-5: все команды на `base1c` выполнены под пользователем ИБ.

# ТЗ v0.2.2 — Унификация файловых команд и исправление семантики

## Цель

Исправить семантическую ошибку v0.2.1: команды `dump-cfu` / `load-cfu` 
работали с расширениями, но использовали имя `.cfu` (которое означает 
обновление конфигурации, а не расширение).

Привести API файловых команд в соответствие с логикой 1С: одна команда 
`/DumpCfg` с опцией `-Extension` работает и для конфигурации, и для 
расширений. Формат файла (`.cf` / `.cfe`) определяет назначение.

## Изменения

### Удалить

- `scripts/actions/dump_cfu.py`
- `scripts/actions/load_cfu.py`
- `tests/test_dump_cfu.py`
- `tests/test_load_cfu.py`

### Изменить dump-cf

Добавить опцию `--extension <имя>`.

Ключ 1С:
    /DumpCfg <файл> [-Extension <имя>]

Валидация:
- Файл `--to` с расширением `.cfe` → `--extension` обязателен.
- Файл `--to` с расширением `.cf` → `--extension` запрещён.
- Другое расширение → WARNING.

### Изменить load-cf

Аналогично: добавить `--extension <имя>`.

Ключ 1С:
    /LoadCfg <файл> [-Extension <имя>] [/UpdateDBCfg]

Валидация аналогична `dump-cf`.

### Обновить scripts/actions/__init__.py

Убрать `DumpCfuAction`, `LoadCfuAction`.

Итоговый список действий (5):
- CreateIbFileAction
- DumpConfigAction
- LoadConfigAction
- DumpCfAction
- LoadCfAction

## Критерии приёмки

- AC-1. `onec-ops dump-cf --to /tmp/base.cf --ib inputs/base1c` 
  создаёт `.cf` (конфигурация).
- AC-2. `onec-ops dump-cf --to /tmp/onec.cfe --extension onec --ib inputs/base1c` 
  создаёт `.cfe` (расширение).
- AC-3. `onec-ops dump-cf --to /tmp/base.cfe --ib inputs/base1c` 
  → ошибка: «.cfe без --extension».
- AC-4. `onec-ops dump-cf --to /tmp/base.cf --extension onec --ib inputs/base1c` 
  → ошибка: «.cf не может иметь --extension».
- AC-5. `load-cf` работает симметрично.
- AC-6. `pytest -v` зелёный.
- AC-7. Skill обновлён.

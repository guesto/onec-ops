# onec-ops

## Когда использовать

- Пользователь просит создать файловую информационную базу 1С.
- Нужно автоматизировать подготовку окружения 1С (в т.ч. в CI).
- Работа с базой 1С через командную строку и открытие GUI в графической сессии.
- Выгрузка и загрузка конфигурации или расширений в XML, `.cf` и `.cfe`.
- Список расширений ИБ, проверка, можно ли применить расширение, удаление расширения.
- Сборка и разборка внешних обработок `.epf` и отчётов `.erf` из/в XML.
- Резервное копирование и восстановление файловой ИБ через `.dt`.
- Создание файлового хранилища конфигурации, его пользователей, подключение ИБ и обновление из него.

## Когда НЕ использовать

- Написание или правка кода 1С (это не про код).
- Автоматизация взаимодействия с окнами: команды только открывают GUI.
- Работа с базой на сервере 1С (пока не поддержано — v0.1.1).

## Работа с дисплеем

Для пакетных команд `onec-ops` САМА управляет виртуальным дисплеем:

- Если задан `DISPLAY` — запускает 1С напрямую.
- Если `DISPLAY` не задан, но есть `xvfb-run` — оборачивает запуск в `xvfb-run -a -s "-nolisten unix"` (виртуальный дисплей, не требует прав root).
- Если ни того, ни другого — ошибка с подсказкой установить xvfb.

### ЗАПРЕЩЕНО (не делай этого)

- НЕ оборачивай `onec-ops` в `xvfb-run` — утилита сделает это сама.
- НЕ запускай `Xvfb` вручную.
- НЕ выставляй `DISPLAY` вручную перед вызовом `onec-ops`.

Вызывай `onec-ops create-ib --type file --path /path/to/ib` — утилита сама выберет режим.

## Доступные команды

| Задача | Команда |
| --- | --- |
| Создать файловую ИБ | `onec-ops create-ib --type file --path /path/to/ib` |
| Перезаписать существующую ИБ | `onec-ops create-ib --type file --path /path/to/ib --force` |
| Перезапись без интерактива (CI) | `onec-ops create-ib --type file --path /path/to/ib --force --yes` |
| Выгрузить конфигурацию в XML | `onec-ops dump-config --to /path/to/xml --ib /path/to/ib` |
| Загрузить конфигурацию из XML | `onec-ops load-config --from /path/to/xml --ib /path/to/ib` |
| Выгрузить конфигурацию в .cf | `onec-ops dump-cf --to /path/to/base.cf` |
| Загрузить конфигурацию из .cf | `onec-ops load-cf --from /path/to/base.cf` |
| Выгрузить расширение в .cfe | `onec-ops dump-cf --to /path/to/ext.cfe --extension Имя` |
| Загрузить расширение из .cfe | `onec-ops load-cf --from /path/to/ext.cfe --extension Имя` |
| Список расширений ИБ | `onec-ops list-extensions --ib /path/to/ib` |
| Проверить, можно ли применить расширение | `onec-ops check-extension --ib /path/to/ib --extension Имя` |
| Удалить расширение | `onec-ops delete-extension --ib /path/to/ib --extension Имя` |
| Открыть Конфигуратор | `onec-ops open-designer --ib /path/to/ib` |
| Открыть клиент 1С | `onec-ops open-enterprise --ib /path/to/ib` |
| Открыть клиент с обработкой | `onec-ops open-enterprise --ib /path/to/ib --execute /path/to/epf.epf` |
| Разобрать обработку .epf/.erf в XML | `onec-ops dump-epf --epf /path/to/file.epf --to /path/to/xml` |
| Собрать обработку .epf/.erf из XML | `onec-ops load-epf --root /path/to/file.xml --epf /path/to/file.epf` |
| Выгрузить базу в .dt | `onec-ops dump-dt --to /path/to/base.dt --ib /path/to/ib` |
| Восстановить базу из .dt | `onec-ops restore-dt --from /path/to/base.dt --ib /path/to/ib` |
| Создать хранилище | `onec-ops repo-create --storage /path/to/storage --ib /path/to/ib` |
| Подключить к хранилищу | `onec-ops repo-bind --storage /path/to/storage --ib /path/to/ib` |
| Обновить из хранилища | `onec-ops repo-update --storage /path/to/storage --ib /path/to/ib` |
| Добавить пользователя хранилища | `onec-ops repo-add-user --storage /path/to/storage --ib /path/to/ib --user Имя --rights LockObjects` |

Для команд конфигурации, расширений и обработок обязательно добавляй `--ib /path/to/ib`.
Для `.cfe` требуется `--extension Имя`; для `.cf` эта опция запрещена.
`restore-dt` перезаписывает данные и конфигурацию существующей ИБ и требует подтверждения `Y`.
Для восстановления без запроса (CI) нужны оба флага `--force --yes`; один `--force` требует подтверждения.
`dump-dt` создаёт родительские каталоги и предупреждает о перезаписи файла.

## Общие параметры

- `--ib PATH` — существующая файловая ИБ с `1Cv8.1CD` (для всех команд, кроме `create-ib`).
- `--ib-user NAME` / `--ib-password PWD` — пользователь ИБ (см. «Пользователь ИБ»).
- `--platform PATH` — путь к 1cv8 (по умолчанию из конфига или ОС); `--config PATH` — TOML-конфиг.
- `--log-level LEVEL` — DEBUG / INFO / WARNING / ERROR; `--log-file PATH` — файл журнала.
- `--dry-run` — показать команду без запуска 1С; `--timeout SEC` — таймаут (по умолчанию 600).

## Пользователь ИБ

Если в ИБ есть пользователи, передай пользователя для ЛЮБОЙ команды с `--ib`
(пакетные и GUI): `--ib-user NAME [--ib-password PWD]` → `/N`, `/P`.
Без него 1С сразу завершается с кодом 1: «Пользователь ИБ не идентифицирован».
Имя нужно и пользователю без пароля.

- Пароль лучше через окружение: `ONEC_OPS_IB_USER` / `ONEC_OPS_IB_PASSWORD`
  (не попадает в историю shell). Параметр CLI важнее окружения.
- Пароль маскируется в журнале; не повторяй его в ответах пользователю.
- `--ib-password` без пользователя — ошибка; для `create-ib` параметры запрещены.
- Не знаешь пользователя или пароль — спроси пользователя, не подбирай.
- `--user` / `--password` у `repo-create` и `repo-add-user` — пользователь
  ХРАНИЛИЩА, а не ИБ; `--storage-user` / `--storage-password` — тоже хранилище.
- У `open-designer` / `open-enterprise` `--user` / `--password` устарели —
  используй `--ib-user` / `--ib-password`.

## Примеры

Новая ИБ: `onec-ops create-ib --type file --path ./my-ib` (создаёт 1Cv8.1CD и служебные файлы). Без запуска 1С: `onec-ops --dry-run create-ib --type file --path /tmp/test` (показывает команду).

## Частые ошибки

| Ошибка | Правильно |
| --- | --- |
| Использовать 1cv8c (тонкий клиент) | Только 1cv8 (толстый клиент) |
| Запускать без --force на существующей ИБ | Добавить --force и подтвердить Y |
| Ожидать интерактив в CI | Использовать --force --yes |
| Запускать без `--ib-user` на ИБ с пользователями | `--ib-user NAME` (+ `ONEC_OPS_IB_PASSWORD`) |
| Гадать о причине «ненулевого кода» | Читать строки после кода в выводе: это текст 1С из `/Out` |

## GUI-команды

GUI-команды (`open-designer`, `open-enterprise`) в Linux требуют реальный DISPLAY.
В headless-окружениях (CI, Docker, sandbox Codex) недоступны; Xvfb не используется.
В Windows запускаются напрямую в графической сессии без DISPLAY.
По умолчанию ждут закрытия окна (таймаут `--timeout`); `--no-wait` возвращает управление сразу.
Dry-run проверяет ИБ и показывает команду без проверки DISPLAY и запуска GUI.

## Хранилище конфигурации

Только файловое хранилище; все команды хранилища требуют существующую ИБ с `1Cv8.1CD`.
`repo-create` создаёт каталог; `--user` по умолчанию «Администратор», `--password` опционален.
`repo-bind` требует непустой каталог; `--force` перезаписывает конфигурацию базы.
`repo-update` требует существующий каталог; `--version N` выбирает версию, `--force` получает новые объекты.
Для подключения и обновления используй `--storage-user` / `--storage-password` при необходимости.
Один пользователь хранилища = одна база. Для второй базы сначала `repo-add-user`
(от имени администратора через `--storage-user`), затем `repo-bind` под новым пользователем.
`repo-add-user`: `--rights` обязателен (`ReadOnly`, `LockObjects`, `ManageConfigurationVersions`,
`Administration`); `--ib` — база этого хранилища или не подключённая ни к какому.
Не подключай вторую базу через `repo-bind --force` под тем же пользователем: первая база будет отвязана.
Dry-run проверяет пути и ИБ, для создания подготавливает каталог, но хранилище не создаёт.

## Расширения

- `list-extensions` печатает в stdout имена расширений по одному в строке
  (журнал — в stderr); пустой stdout — расширений нет. Используй перед
  `dump-config --extension` / `dump-cf --extension`, чтобы узнать имена.
  В списке и не применённые к БД расширения — применимость проверяй `check-extension`.
- `check-extension` (`--extension Имя` или `--all-extensions`) ничего не меняет:
  код 0 — можно применить, код 1 — причины 1С в выводе. Запускай после
  `load-cf --extension` и после обновления основной конфигурации.
- `delete-extension` необратимо удаляет расширение ВМЕСТЕ С ДАННЫМИ его
  объектов. Требует подтверждения `Y`; `--yes` — только если пользователь
  явно попросил удалить. Без TTY и без `--yes` — ошибка.
- Для `check-extension` и `delete-extension` нужно ровно одно:
  `--extension Имя` или `--all-extensions`.

# Roadmap onec-ops

CLI-утилита и Agent Skill для автоматизации пакетных операций 1С:Предприятие.

## Принципы

- **Итеративность.** Каждый релиз — маленький, проверяемый, с тестами.
- **Кроссплатформенность.** Linux + Windows, DISPLAY + xvfb-run.
- **Двойное назначение.** Утилита работает и для человека (CLI), 
  и для ИИ-агента (Agent Skill).

## Состояние

**Текущий релиз:** v0.8.0 [В РАБОТЕ] (полировка Skill).
**Завершённые:** v0.1.0, v0.2.0, v0.2.1, v0.2.2, v0.2.3, v0.3.0,

### v0.1.0 — Фундамент: дисплей + файловая ИБ [ГОТОВО]

**Дата:** 2026-10-03

- Кроссплатформенный `runner` (Linux DISPLAY / xvfb-run, Windows direct).
- Проверка окружения: `DISPLAY`, `xvfb-run`, платформа 1С.
- Команда `create-ib --type file --path <path>` — создание файловой ИБ.
- Безопасный `--force`: интерактивное подтверждение Y/n, `--yes` для CI.
- Таймаут 600 с, UTF-8-декодирование, маскирование паролей.
- `xvfb-run -a -s "-nolisten unix"` — работа без прав root.
- Unit-тесты: 20 passed, покрытие 71%.
- Agent Skill: `SKILL.md`, `agents/openai.yaml`, `references/commands.md`.
- Установка через `pipx` как глобальная команда `onec-ops`.
- Skill протестирован в Codex (end-to-end, создание ИБ).

**Известные ограничения:**
- Codex в sandbox-режиме не может запускать 1С (X11 заблокирован).
- `create-ib --type server` — заглушка (v0.3.1).

### v0.2.1 — Файловые команды [ГОТОВО]

**Дата:** 2026-10-06

- `load-cf` — загрузка конфигурации из `.cf`.

### v0.2.2 — Унификация файловых команд [ГОТОВО]

**Дата:** 2026-10-06

- Удалены `dump-cfu` / `load-cfu` (семантически неверные имена).
- Унифицированы `dump-cf` / `load-cf` — работают и с конфигурацией 
  (`.cf`), и с расширением (`.cfe`) через опцию `--extension`.
- Валидация по расширению файла:
  - `.cfe` без `--extension` → ошибка.
  - `.cf` с `--extension` → ошибка.
  - Другое расширение → WARNING.
- 98 тестов, покрытие 93%.
- Round-trip на реальной 1С — чистый.

### v0.3.0 — Внешние обработки и отчёты [ГОТОВО]

**Дата:** 2026-10-11

- `dump-epf` — разборка `.epf` / `.erf` в XML.
  - `--epf <файл.epf|erf> --to <каталог>`
  - `/DumpExternalDataProcessorOrReportToFiles`
- `load-epf` — сборка `.epf` / `.erf` из XML.
  - `--root <файл.xml> --epf <файл.epf|erf>`
  - `/LoadExternalDataProcessorOrReportFromFiles`
- Единый API для обработок и отчётов (по расширению).
- 178 тестов, покрытие 95%.
- Round-trip на реальной 1С (8.5.1.1343):
  - `dump-epf` → XML-выгрузка за 1.43 с.
  - `load-epf` → `.epf` создан (5632 байта, идентичен оригиналу).
  - `diff` между выгрузками — чистый.

### v0.4.0 — Бэкапы базы (DT) [ГОТОВО]

**Дата:** 2026-10-19

- `dump-dt` — выгрузка базы в `.dt` (`/DumpIB`).
  - `--ib <источник> --to <файл.dt>`
  - Создаёт родительские каталоги, предупреждает о перезаписи файла.

- 222 теста, покрытие 96%.

### v0.5.0 — Хранилище конфигурации (файловое) [ГОТОВО]

**Дата:** 2026-10-20

- `repo-create` — создание хранилища (`/ConfigurationRepositoryCreate`).
- `repo-bind` — подключение базы к хранилищу (`/ConfigurationRepositoryBindCfg`).
- `repo-update` — обновление из хранилища (`/ConfigurationRepositoryUpdateCfg`).
- Разделение аутентификации: ИБ (`/N`, `/P`) vs хранилище 
  (`--storage-user` / `--storage-password` → 
  `/ConfigurationRepositoryN`, `/ConfigurationRepositoryP`).
- 265 тестов, покрытие 96%.

**Известные ограничения:**
- Только файловое хранилище (без `crserver`, tcp://, http://).
- Один пользователь хранилища = одна база; для нескольких баз нужны 
  отдельные пользователи (v0.5.1).
- `repo-add-user`, запланированный в v0.5.0, перенесён в v0.5.1.

### v0.5.1 — Пользователи хранилища [ГОТОВО]

**Дата:** 2026-10-22

**ТЗ:** [docs/v0.5.1.md](docs/v0.5.1.md).

- `repo-add-user` — добавление пользователя в хранилище 
  (`/ConfigurationRepositoryAddUser`).

    `Administration`.
  - `--restore-deleted` — восстановить ранее удалённого пользователя.

- Снимает ограничение v0.5.0: несколько баз — разные пользователи.
- 285 тестов, покрытие 96%.
- Проверено на реальной 1С (8.5.1.1343): вторая база подключена

**Известные ограничения:**
- `--ib` должна быть подключена к этому хранилищу или не подключена 
  ни к какому.
- Текст ошибки 1С не выводился, только код возврата (исправлено в v0.5.2).

### v0.6.0 — Расширения [ГОТОВО]

**Дата:** 2026-10-23

**ТЗ:** [docs/v0.6.0.md](docs/v0.6.0.md).

Выгрузка и загрузка расширений реализованы раньше — через 
унифицированный API `--extension` в v0.2.0 и v0.2.2:

- `dump-config --extension <имя>` / `--all-extensions` — выгрузка в XML.
- `load-config --extension <имя>` — загрузка из XML.
- `dump-cf --extension <имя>` / `load-cf --extension <имя>` — `.cfe`.

Новое в v0.6.0:

- `list-extensions` — список расширений ИБ в stdout (`/DumpDBCfgList`).
- `check-extension` — можно ли применить расширение 
  (`/CheckCanApplyConfigurationExtensions`).
- `delete-extension` — удаление расширения с подтверждением (`/DeleteCfg`).
- `run_1c` возвращает текст `/Out` (`out_text`).
- Skill: 3 новые команды.
- 395 тестов, покрытие 97%.
- Проверено на реальной 1С (8.5.1.1343): список, проверка совместимой 
  и несовместимой базы, удаление, несуществующее расширение.

**Известные ограничения:**
- В `list-extensions` попадают и не применённые к БД расширения.
- Свойства расширений (безопасный режим, активность) не поддержаны.

## Технические решения (накопленные)

### Запуск 1С

- **Толстый клиент `1cv8`** для всех пакетных операций. Тонкий `1cv8c` 
  не поддерживает `CREATEINFOBASE` и большинство операций Конфигуратора.
- **Linux + DISPLAY** — прямой запуск `1cv8`.
- **Linux без DISPLAY + xvfb-run** — `xvfb-run -a -s "-nolisten unix" 1cv8`.
- **Linux без DISPLAY и без xvfb-run** — ошибка `XvfbNotAvailable`.
- **Windows** — прямой запуск `1cv8.exe`.
- **GUI-команды** — требуют реальный `DISPLAY` (не Xvfb), проверка 
  через `xdpyinfo`.

### Agent Skill

- Пакет навыка: `SKILL.md` + `references/` + `agents/` в корне проекта; 
  `SKILL.md` ссылается только внутрь пакета.
- В проекте: симлинки `SKILL.md`, `references`, `agents` в 
  `.claude/skills/onec-ops/` (каталог не в git, создаётся после clone).
- Глобально: **копирование** пакета в `~/.claude/skills/onec-ops/` и 
  `~/.codex/skills/onec-ops/` (Codex не следует симлинкам); копии 
  обновляются вручную после релиза.
- `tests/test_skill.py` ловит дрейф: каждая команда CLI есть в `SKILL.md` 
  и `references/commands.md`, ссылки не выходят за пакет.

### Codex и sandbox

- В sandbox-режиме Codex X11 заблокирован, 1С не запускается.
- Решение: `sandbox_mode = "danger-full-access"` в `~/.codex/config.toml`.
- Skill документирует это ограничение и не пытается обойти.
- GUI-команды в sandbox недоступны — понятная ошибка.

### Установка

- **Для разработки:** `pip install -e ".[dev]"` в venv.
- **Для использования:** `pipx install git+https://github.com/guesto/onec-ops.git`.
- **Для публикации (v0.9.0):** `pipx install onec-ops` из PyPI.

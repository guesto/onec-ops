# Roadmap onec-ops

CLI-утилита и Agent Skill для автоматизации пакетных операций 1С:Предприятие.

## Принципы

- **Итеративность.** Каждый релиз — маленький, проверяемый, с тестами.
- **Кроссплатформенность.** Linux + Windows, DISPLAY + xvfb-run.
- **Двойное назначение.** Утилита работает и для человека (CLI), 
  и для ИИ-агента (Agent Skill).

## Состояние

**Текущий релиз:** v0.3.0 [ПЛАНИРУЕТСЯ] (внешние обработки).

### v0.2.2 — Унификация файловых команд [ГОТОВО]

**Дата:** 2026-10-06

### v0.2.3 — GUI-команды [ГОТОВО]

**Дата:** 2026-10-10

- `open-designer` — открыть интерактивный Конфигуратор.
- `open-enterprise` — открыть клиент 1С:Предприятие.
- Опции: `--user`, `--password`, `--no-wait`.
- Для `open-enterprise`: `--execute <файл.epf>`, `--c <параметр>`.
- Реальная проверка DISPLAY через `xdpyinfo`.
- Определение sandbox Codex (`_detect_codex_sandbox`).
- Запуск через `Popen` (для `--no-wait`).
- 143 теста, покрытие 95%.
- Проверено на реальной 1С (8.5.1.1343):
  - `open-designer` открывает Конфигуратор (46.78 с).
  - `--no-wait` возвращает управление сразу (PID 21292).
  - `open-enterprise` открывает клиент (7.45 с).
  - `--execute` запускает обработку (10.41 с).
  - Валидация без DISPLAY — понятная ошибка, код 1.

**Известные ограничения:**
- В sandbox Codex GUI-команды недоступны (X11 изолирован).
- Требуется реальный DISPLAY (не Xvfb).

### v0.6.0 — Расширения [ГОТОВО]

**Дата:** реализовано в v0.2.0 и v0.2.2.

Основные операции с расширениями уже работают через унифицированный 
API `--extension`:

- `dump-config --extension <имя>` — выгрузка расширения в XML.
- `load-config --extension <имя>` — загрузка расширения из XML.
- `dump-config --all-extensions` — выгрузка всех расширений.
- `dump-cf --extension <имя>` — выгрузка `.cfe`.
- `load-cf --extension <имя>` — загрузка `.cfe`.

**Принцип:** одна команда с опцией `--extension` работает и для 
конфигурации, и для расширений — по аналогии с ключами 1С.

**Что может быть добавлено позже** (если будет реальная задача):

- `list-extensions` — список загруженных расширений.
- `delete-extension` — удаление расширения.
- `check-extension` — проверка на ошибки.

## Технические решения (накопленные)

### Запуск 1С

- **Толстый клиент `1cv8`** для всех пакетных операций. Тонкий `1cv8c` 
  не поддерживает `CREATEINFOBASE` и большинство операций Конфигуратора.
- **Linux + DISPLAY** — прямой запуск `1cv8`.
- **Linux без DISPLAY + xvfb-run** — `xvfb-run -a -s "-nolisten unix" 1cv8`.
- **Linux без DISPLAY и без xvfb-run** — ошибка `XvfbNotAvailable`.
- **Windows** — прямой запуск `1cv8.exe`.
- **GUI-команды** — требуют реальный `DISPLAY` (не Xvfb), проверка через `xdpyinfo`.

### Agent Skill

- Канонический `SKILL.md` в корне проекта.
- Установка в Codex через **копирование** (не symlinks) 
  в `~/.codex/skills/onec-ops/`.
- Установка в Claude Code через `~/.claude/skills/onec-ops/`.
- Skill наполняется постепенно, по мере роста команд.

### Codex и sandbox

- В sandbox-режиме Codex X11 заблокирован, 1С не запускается.
- Решение: `sandbox_mode = "danger-full-access"` в `~/.codex/config.toml`.
- Skill документирует это ограничение и не пытается обойти.
- GUI-команды в sandbox недоступны — понятная ошибка.

### Установка

- **Для разработки:** `pip install -e ".[dev]"` в venv.
- **Для использования:** `pipx install git+https://github.com/guesto/onec-ops.git`.
- **Для публикации (v0.9.0):** `pipx install onec-ops` из PyPI.

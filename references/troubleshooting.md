# Устранение неполадок onec-ops

## Codex sandbox: Xvfb не запускается

**Симптом:**

    *** Unable to initialize GTK+ or connect to the windowing system.

В журнале также может появиться сообщение «Xvfb не запущен».

**Причина:** в Linux-окружении Codex с режимом `workspace-write` `/tmp`
может быть изолирован через tmpfs в отдельном mount namespace. В описанном
случае `/tmp/.X11-unix` внутри песочницы принадлежит `nobody:nogroup`,
а проверка владельца каталога Xvfb ожидает `root:root`.
Чтобы подтвердить именно эту причину, выполните диагностику.

**Диагностика** (в чате Codex):

    cat /proc/self/mountinfo | grep " /tmp "
    ls -ld /tmp/.X11-unix

Признак: `/tmp` — отдельная tmpfs, владелец `/tmp/.X11-unix` — `nobody:nogroup`.

**Решение — добавить настройки для текущего проекта.**

Попросите Codex в чате:

    Добавь для текущего проекта настройки в .codex/config.toml:
    sandbox_mode = "danger-full-access"
    approval_policy = "on-request"

Codex добавит их в `<путь-к-проекту>/.codex/config.toml`:

    sandbox_mode = "danger-full-access"
    approval_policy = "on-request"

Codex загружает локальные настройки только для доверенных проектов.
Таблица `[projects."<путь-к-проекту>"]` в `~/.codex/config.toml` предназначена
для `trust_level`; параметры sandbox задавайте в конфиге самого проекта.
См. [официальную документацию по конфигурации](https://learn.chatgpt.com/docs/config-file/config-basic)
и [справочник настроек](https://learn.chatgpt.com/docs/config-file/config-reference).

После изменения проверьте фактический режим следующего запуска команды.
Если активная сессия сохраняет прежнюю изоляцию, начните новую сессию Codex
для этого проекта. Не рассчитывайте на применение настроек без перезапуска
сессии во всех версиях клиента.

**Проверка** (в чате Codex после применения настроек):

    ls -ld /tmp
    ls -ld /tmp/.X11-unix

Ожидание для описанного окружения: владелец `root` (или пользователь),
а не `nobody`; команды больше не видят изолированную tmpfs песочницы.

**Альтернатива — CLI-флаг:**

    codex --sandbox danger-full-access --ask-for-approval on-request

Запускайте эту команду из каталога проекта. Утилита `onec-ops` сама выберет
прямой запуск 1С или `xvfb-run` в зависимости от окружения.

**Что НЕ делать:**

- Не запускать Xvfb вручную.
- Не использовать sudo в песочнице.
- Не менять владельцев каталогов на хосте: в песочнице `/tmp` изолирован.

**Безопасность:** `danger-full-access` даёт Codex полный доступ.
Применяйте только для доверенных проектов. Настройку выполняйте по явному
запросу пользователя; не пытайтесь самостоятельно обойти ограничения.

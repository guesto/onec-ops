## Платформа 1С не найдена

**Симптом:** `Платформа 1С не найдена или не исполняема: <путь>`.

**Причина:** по умолчанию ожидается `/opt/1cv8/x86_64/8.5.1.1343/1cv8`
(Windows: `C:\Program Files\1cv8\8.5.1.1343\bin\1cv8.exe`), а у пользователя
другая версия или путь.

**Решение** (по приоритету): `--platform PATH`, переменная
`ONEC_OPS_PLATFORM`, ключ `platform` в `~/.config/onec-ops/config.toml`.
Найти установленные версии: `ls /opt/1cv8/x86_64/`.

## Нет DISPLAY и xvfb-run

**Симптом:** `Нет DISPLAY и не найден xvfb-run. Установите xvfb или задайте DISPLAY.`

**Решение:** попроси пользователя установить xvfb (`sudo apt install xvfb`)
или запустить команду в графической сессии. Не запускай Xvfb вручную и не
выставляй `DISPLAY` сам.

## Тонкий клиент 1cv8c

**Симптом:** пакетная команда падает или висит, в `--platform` указан `1cv8c`.

**Причина:** тонкий клиент не поддерживает `CREATEINFOBASE`, `DumpCfg`,
`LoadCfg`, `DumpIB` и работу с хранилищем.

**Решение:** путь к толстому клиенту `1cv8` той же версии.

## Таймаут

**Симптом:** `1С не завершилась за 600 секунд. Возможные причины: открыт
диалог, отсутствует база, проблемы с лицензией.`

**Решение:**
- Если после сообщения есть текст 1С — исправь причину по нему.
- Большая база (`dump-dt`, `restore-dt`, `load-cf`) — увеличь `--timeout`.
- База открыта в Конфигураторе или клиенте у пользователя — попроси закрыть.
- Проблемы с лицензией — сообщи пользователю, не обходи.

## GUI-команды без дисплея

**Симптомы:** `GUI-команды требуют реальный DISPLAY`,
`X-сервер на DISPLAY=… не отвечает`, `GUI-команды недоступны в
sandbox-режиме Codex`.

**Причина:** `open-designer` и `open-enterprise` открывают окно, Xvfb для
них не используется.

**Решение:** попроси пользователя выполнить команду в терминале его
графической сессии. Проверить аргументы можно через `--dry-run`.

## Требуется интерактивное подтверждение

**Симптомы:** `--force требует интерактивного подтверждения`,
`Восстановление требует интерактивного подтверждения`,
`Удаление расширения требует интерактивного подтверждения`.

**Причина:** `create-ib --force`, `restore-dt`, `delete-extension` ждут
ответа `Y`, а терминала нет (агент, CI).

**Решение:** опиши пользователю, что будет перезаписано или удалено, и
спроси. Только после явного согласия добавь `--force --yes`
(`create-ib`, `restore-dt`) или `--yes` (`delete-extension`).

## unrecognized arguments

**Симптом:** `onec-ops: error: unrecognized arguments: …`, код 2.

**Частые причины:**
- `--user` / `--password` у пакетных команд — нужен `--ib-user` /
  `--ib-password` (у `repo-create` / `repo-add-user` `--user` — пользователь
  хранилища).
- Параметр другой команды: проверь `onec-ops <команда> --help`.

## Codex sandbox: Xvfb не запускается

**Симптом:**

    *** Unable to initialize GTK+ or connect to the windowing system.

В журнале также может появиться сообщение «Xvfb не запущен».

**Причина:** в Linux-окружении Codex с режимом `workspace-write` `/tmp`
может быть изолирован через tmpfs в отдельном mount namespace. В описанном
случае `/tmp/.X11-unix` внутри песочницы принадлежит `nobody:nogroup`,
а проверка владельца каталога Xvfb ожидает `root:root`.
Чтобы подтвердить именно эту причину, выполните диагностику.

**Диагностика** (в чате Codex):

    cat /proc/self/mountinfo | grep " /tmp "
    ls -ld /tmp/.X11-unix

Признак: `/tmp` — отдельная tmpfs, владелец `/tmp/.X11-unix` — `nobody:nogroup`.

**Решение — добавить настройки для текущего проекта.**

Попросите Codex в чате:

    Добавь для текущего проекта настройки в .codex/config.toml:
    sandbox_mode = "danger-full-access"
    approval_policy = "on-request"

Codex добавит их в `<путь-к-проекту>/.codex/config.toml`:

    sandbox_mode = "danger-full-access"
    approval_policy = "on-request"

Codex загружает локальные настройки только для доверенных проектов.
Таблица `[projects."<путь-к-проекту>"]` в `~/.codex/config.toml` предназначена
для `trust_level`; параметры sandbox задавайте в конфиге самого проекта.
См. [официальную документацию по конфигурации](https://learn.chatgpt.com/docs/config-file/config-basic)
и [справочник настроек](https://learn.chatgpt.com/docs/config-file/config-reference).

После изменения проверьте фактический режим следующего запуска команды.
Если активная сессия сохраняет прежнюю изоляцию, начните новую сессию Codex
для этого проекта. Не рассчитывайте на применение настроек без перезапуска
сессии во всех версиях клиента.

**Проверка** (в чате Codex после применения настроек):

    ls -ld /tmp
    ls -ld /tmp/.X11-unix

Ожидание для описанного окружения: владелец `root` (или пользователь),
а не `nobody`; команды больше не видят изолированную tmpfs песочницы.

**Альтернатива — CLI-флаг:**

    codex --sandbox danger-full-access --ask-for-approval on-request

Запускайте эту команду из каталога проекта. Утилита `onec-ops` сама выберет
прямой запуск 1С или `xvfb-run` в зависимости от окружения.

**Что НЕ делать:**

- Не запускать Xvfb вручную.
- Не использовать sudo в песочнице.
- Не менять владельцев каталогов на хосте: в песочнице `/tmp` изолирован.

**Безопасность:** `danger-full-access` даёт Codex полный доступ.
Применяйте только для доверенных проектов. Настройку выполняйте по явному
запросу пользователя; не пытайтесь самостоятельно обойти ограничения.

## Ошибки 1С

### Ошибка: «Попытка связывания информационной базы пользователем...»

**Причина:** 1С не разрешает подключать вторую базу к хранилищу 
тем же пользователем.

**Решение:**
- `repo-bind --force` с `-forceBindAlreadyBindedUser` — 
  перепривязка (отвязывает старую, привязывает новую).
- Или создать отдельного пользователя: `repo-add-user --user <имя> 
  --rights LockObjects` и подключить базу под ним.

### Ошибка: «Пользователь ИБ не идентифицирован»

**Причина:** в ИБ есть список пользователей, а команда запущена без
пользователя или с неверным паролем. 1С завершается сразу с кодом 1
(не ждёт таймаута). Имя нужно передавать и пользователю без пароля.

**Решение:** `--ib-user NAME [--ib-password PWD]` или переменные окружения
`ONEC_OPS_IB_USER` / `ONEC_OPS_IB_PASSWORD`. Не путайте с `--user` /
`--password` у `repo-create` и `repo-add-user` — это пользователь хранилища.

### Ошибка: «Расширение нельзя применить»

**Симптом:** `check-extension` (или `load-cf --extension … --update-db-cfg`)
завершается с кодом 1, в тексте 1С: `<имя>: Не найден объект …`,
`… не совпадает со значением в расширяемой конфигурации`.

**Причина:** расширение рассчитано на другую версию основной конфигурации.

**Решение:** сообщи пользователю список причин. Расширение нужно
доработать под конфигурацию (это не задача `onec-ops`) или удалить:
`delete-extension` — только с согласия, данные его объектов будут потеряны.

### Ошибка: «Расширение не найдено»

**Симптом:** `Операция не может быть выполнена, так как расширение
конфигурации с указанным именем не найдено: <имя>`.

**Решение:** узнай точные имена через `list-extensions`.

### Ошибка: «Конфигурация связана с другим хранилищем»

**Причина:** база `--ib` уже подключена к другому хранилищу. Встречается 
в `repo-add-user` и `repo-bind`.

**Решение:**
- Для `repo-add-user` укажите базу, подключённую к этому хранилищу, 
  или не подключённую ни к какому (например, исходную базу хранилища).
- Для `repo-bind` используйте `--force` (перезапишет конфигурацию базы) 
  или новую пустую ИБ.
  
### Где искать текст ошибки 1С

**Симптом (до v0.5.2):** в выводе только «1С завершилась с ненулевым кодом: 1».

**Причина:** у `1cv8 DESIGNER` и `1cv8 CREATEINFOBASE` stdout и stderr пустые;
сообщения 1С пишет только в файл ключа `/Out <файл>`.

**Начиная с v0.5.2:** `onec-ops` сам передаёт `/Out` во временный файл
для пакетных команд, после завершения пишет содержимое в журнал
(«Сообщения 1С (/Out): …») и при ошибке добавляет его в сообщение CLI:

    1С завершилась с ненулевым кодом: 1
    Пользователь хранилища конфигурации с именем 'user2' уже существует.
    Создание пользователя хранилища конфигурации завершилось с ошибкой

Временный файл удаляется. Чтобы сохранить сообщения в своём файле,
используйте `--log-file`. GUI-команды (`open-designer`, `open-enterprise`)
`/Out` не получают: их сообщения показываются в окнах 1С.

**Ручная проверка** (команду берите из журнала `onec-ops`, пароли в нём
скрыты как `***`):

    1cv8 DESIGNER /F <ib> ... /Out out.txt
    cat out.txt    # UTF-8 с BOM
